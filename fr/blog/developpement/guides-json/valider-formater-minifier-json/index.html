Valider, formater ou minifier du JSON : que choisir ?

Choisissez entre vérifier la syntaxe, rendre le JSON plus lisible et produire un texte compact, en sachant ce que chaque action change.

Publié: 30 septembre 2026
Catégories: Guides JSON

Validez le JSON pour vérifier sa syntaxe ; formatez-le pour le lire ou le modifier avec une indentation ; minifiez-le pour obtenir une représentation compacte. L’outil vérifie la syntaxe avant de formater ou de minifier. Si l’entrée est invalide, aucune de ces actions ne la répare.

Votre objectif Choisissez Résultat visible À retenir
Savoir si la syntaxe est valide Valider Un état ou un diagnostic, sans nouveau document Cela ne vérifie pas les règles de données de votre application.
Lire ou modifier la structure Formater Du JSON avec des retours à la ligne et une indentation Un résultat n’est produit que si l’entrée peut être analysée.
Obtenir un texte compact Minifier Du JSON sérialisé sans espaces de présentation Cela ne crée pas de fichier compressé.

Essayez l’action choisie dans le formateur et validateur JSON. Conservez l’original si vous comptez copier un résultat transformé.

Un document, trois résultats différents

Utilisez cette même entrée valide pour les trois actions :

{"produit":"Cahier", "actif":true, "etiquettes":["papier","bleu"]}

Valider affiche JSON valide. La validation ne crée pas de nouveau document : elle confirme uniquement que le texte peut être analysé comme du JSON.

Formater avec une indentation de deux espaces produit une version plus facile à lire :

{
  "produit": "Cahier",
  "actif": true,
  "etiquettes": [
    "papier",
    "bleu"
  ]
}

Minifier produit un texte compact sur une ligne :

{"produit":"Cahier","actif":true,"etiquettes":["papier","bleu"]}

Dans cet exemple, les deux transformations représentent les mêmes champs et valeurs analysés ; leur présentation change. La spécification JSON autorise des espaces de présentation entre les éléments de syntaxe. Leur suppression ne crée pas de fichier ZIP et ne garantit pas de meilleures performances réseau.

Si l’entrée est invalide

{"produit":} ne contient aucune valeur après les deux-points. La validation signale une erreur de syntaxe. Le formatage et la minification ne peuvent pas non plus produire de sortie JSON : corrigez d’abord l’entrée, puis vérifiez-la à nouveau. Pour trouver la cause, consultez le guide sur les erreurs de syntaxe JSON.

Avant d’utiliser le résultat

Le formatage et la minification analysent puis sérialisent à nouveau le document. Ils ne garantissent donc pas la conservation du texte octet pour octet : l’outil avertit que, pour les clés en double, la dernière valeur prévaut et que les grands entiers peuvent perdre en précision. Si vos données présentent ces cas, lisez l’avertissement et comparez le résultat à l’original avant de l’utiliser.

Ces trois actions concernent la syntaxe. Elles ne vérifient ni les champs obligatoires, ni les types définis par un JSON Schema, ni les règles métier. Vérifiez ces exigences séparément après avoir confirmé que le document est valide.
