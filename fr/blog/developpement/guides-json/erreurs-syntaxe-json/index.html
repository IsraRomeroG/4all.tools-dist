Erreurs de syntaxe JSON : les trouver et les corriger

Repérez une virgule, un guillemet ou une accolade incorrecte, apportez la correction minimale et vérifiez que votre JSON est valide.

Pour corriger une erreur de syntaxe JSON, validez le texte, examinez la position indiquée et le caractère précédent, faites une correction minimale, puis validez à nouveau. L’emplacement signalé peut correspondre au moment où l’analyseur ne comprend plus le document ; la cause peut se trouver sur la ligne précédente.

  1. Collez le document complet dans le validateur JSON et sélectionnez Valider le JSON.
  2. Si le diagnostic indique une ligne et une colonne, examinez cette zone et la fin de la ligne précédente.
  3. Corrigez un problème à la fois : virgule manquante ou superflue, guillemet ou délimiteur de fermeture.
  4. Validez le document complet après chaque modification.

Gardez une copie de l’original pour revoir vos modifications. Le validateur signale les problèmes ; vous choisissez la correction.

Comment interpréter la position d’une erreur

Une virgule manquante peut être détectée seulement à l’arrivée de la clé suivante. Un délimiteur de fermeture absent peut être signalé à la fin du texte. Examinez donc les caractères autour de la position indiquée avant de supprimer celui qui est surligné.

Le message et la position dépendent du programme qui analyse le JSON. MDN présente des exemples de diagnostics d’analyse ; les autres analyseurs peuvent employer des formulations différentes.

Si aucune position n’apparaît, parcourez le document depuis le début et observez où chaque valeur se termine et où la suivante commence. Dans un grand fichier, revenez d’abord à la zone que vous venez de modifier. Ajouter des retraits manuellement peut faciliter la lecture de la structure, mais l’indentation seule ne corrige pas l’erreur.

Exemple : l’erreur vise une clé, mais il manque une virgule avant

Ce document est invalide :

{
  "commande": {
    "id": "A-17"
    "total": 42
  }
}

L’analyseur peut signaler "total" ou une position proche. La clé est correctement écrite : il manque la virgule qui la sépare du champ précédent. Ajoutez-la après "A-17" :

{
  "commande": {
    "id": "A-17",
    "total": 42
  }
}

Collez cette seconde version, puis sélectionnez à nouveau Valider le JSON. Le résultat attendu est JSON valide. L’identifiant et le total restent identiques ; seul le séparateur manquant a été ajouté.

Quatre erreurs qu’une petite modification peut corriger

Les entrées de la deuxième colonne sont volontairement invalides. La dernière colonne contient des documents JSON valides :

Problème Entrée invalide Correction minimale Résultat valide
Virgule manquante entre deux champs {"id":"A-17" "total":42} Ajouter une virgule après l’identifiant. {"id":"A-17","total":42}
Virgule superflue en fin de tableau {"etiquettes":["un","deux",]} Retirer la virgule après "deux". {"etiquettes":["un","deux"]}
Clé entourée d’apostrophes {'actif':true} Remplacer les apostrophes par des guillemets doubles. {"actif":true}
Objet non fermé {"actif":true Ajouter } à la fin. {"actif":true}

Les virgules séparent les champs d’un objet ou les éléments d’un tableau ; les clés et les valeurs textuelles sont délimitées par des guillemets doubles. Ces règles font partie de la syntaxe JSON définie par ECMA-404.

Si le document contient des commentaires

JSON strict n’autorise pas les commentaires. Si l’original est une configuration JSONC, consultez la différence entre JSON et JSONC et la procédure de conversion. Cette conversion retire commentaires et virgules finales ; gardez l’original si ses annotations sont nécessaires pour maintenir la configuration.

Si le problème se trouve dans une chaîne

Dans {"note":"Elle a dit "bonjour""}, les guillemets de "bonjour" ferment la chaîne trop tôt. Échappez-les pour les conserver dans le texte :

{"note":"Elle a dit \"bonjour\""}

Évitez de remplacer tous les guillemets automatiquement : certains caractères peuvent appartenir à la valeur elle-même.

Si le document se termine trop tôt

Dans le dernier exemple du tableau, il manque uniquement une accolade. Si l’entrée s’arrête au milieu d’un texte ou d’un enregistrement, vérifiez d’abord que vous avez copié ou reçu le document entier. Ajouter des délimiteurs de fermeture peut produire une syntaxe valide sans restituer les données manquantes.

Vérifiez la correction et le sens des données

Validez à nouveau le document entier, même si vous n’avez modifié qu’une ligne. Si une autre erreur apparaît, reprenez la procédure. Une fois la validation réussie, choisissez entre le formatage et la minification et vérifiez les valeurs avant de l’enregistrer.

Vérifiez également ce que l’application attend. {"total":"42"} et {"total":42} sont des JSON valides, mais le premier contient du texte et le second un nombre. La validation syntaxique n’applique pas de JSON Schema et ne vérifie pas les règles métier.

Si l’outil signale une limite de taille, une annulation ou un échec de lecture, traitez ce message avant de modifier la ponctuation : il ne prouve pas une erreur de syntaxe. Pour revoir les objets, tableaux et types, consultez le guide expliquant ce qu’est JSON.
