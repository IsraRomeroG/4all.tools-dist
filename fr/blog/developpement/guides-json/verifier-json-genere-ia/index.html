JSON généré par IA : le réparer et vérifier le résultat

Conservez la réponse originale, examinez les modifications proposées et décidez si vous pouvez utiliser le JSON ou devez demander les données complètes.

Gardez la réponse originale de l’IA avant de modifier le JSON. S’il se trouve dans un bloc Markdown, copiez le contenu du bloc et validez-le d’abord. Il n’y a peut-être rien à réparer. Si une réparation est nécessaire, comparez le résultat à l’original avant de l’utiliser : corriger la syntaxe ne restitue pas les données manquantes. Pour les retrouver, il faudra consulter la source ou demander une réponse complète.

Que faire avec la réponse reçue

  1. Gardez une copie de la réponse entière pour comparer les modifications.
  2. Si elle contient un seul bloc Markdown complet, copiez uniquement le document à l’intérieur. Si du texte et plusieurs blocs sont mêlés, identifiez d’abord le document correspondant à votre tâche.
  3. Validez le document. Si sa syntaxe est déjà correcte, passez à la vérification des données ; la réparation est facultative.
  4. Si une réparation est nécessaire, ouvrez l’outil de réparation JSON, collez l’original dans Texte d’entrée, choisissez Réparer JSON, puis sélectionnez Réparer. Coller ou changer de mode ne lance pas l’opération.
  5. Vérifiez la sortie proposée, l’avertissement et les modifications. Comparez les valeurs et les champs avec l’original complet ou la source.
  6. Après avoir vérifié les modifications et les données dont votre application a besoin, sélectionnez Copier la sortie.
Ce que vous avez reçu Première action Ce qu’il faut vérifier
Un bloc Markdown complet contenant du JSON valide Copier uniquement le JSON et le valider. Seule l’enveloppe a été retirée.
Du JSON avec commentaires ou virgules finales Utiliser JSONC vers JSON ; consultez le guide JSON et JSONC. Ces extensions sont retirées et les valeurs conservées.
D’autres erreurs, comme des apostrophes ou des clés sans guillemets Corriger l’erreur à la main si vous savez comment faire, ou essayer Réparer JSON. Ce que l’outil a modifié et les valeurs qu’il a ajoutées.
Un document coupé au milieu d’une valeur ou d’un enregistrement Demander le document complet ou consulter la source. Le contenu manquant ; ajouter des délimiteurs de fermeture ne le restitue pas.

Si vous avez repéré l’erreur et souhaitez la corriger à la main, consultez comment corriger les erreurs de syntaxe JSON. Quand la réponse mêle des explications et plusieurs blocs de code, repérez d’abord le JSON dont vous avez besoin. L’outil ne peut pas choisir à votre place le document à utiliser.

Un bloc Markdown complet : retirer l’enveloppe

Voici la réponse d’exemple, avec ses marqueurs Markdown :

```json
{"commande":"A-17","quantite":2,"livree":false}
```

Données attendues après avoir retiré uniquement l’enveloppe :

{"commande":"A-17","quantite":2,"livree":false}

Le JSON dans le bloc est déjà valide : il suffit de le copier et de le valider. Lors du test avec la réponse entière, Réparer JSON a retiré les marqueurs Markdown et conservé les sauts de ligne autour du document. Les données obtenues sont celles de l’exemple ci-dessus.

Vérifiez que commande contient toujours la chaîne "A-17", quantite le nombre 2 et livree le booléen false. Dans cet exemple, seuls les marqueurs Markdown doivent disparaître. Le rapport peut regrouper plusieurs modifications : comparez aussi le contenu, sans vous fier uniquement au nombre de changements signalés.

Ce mode affiche l’avertissement « La réparation est heuristique et peut modifier le sens. Vérifiez chaque changement. » Pour cette opération, le diagnostic indique aussi : « La sortie vient d’une réparation heuristique. Vérifiez qu’elle conserve le sens attendu. » L’avertissement du mode reste visible même lorsqu’une entrée valide passe sans modification.

Un document tronqué : une valeur ajoutée n’est pas une valeur retrouvée

Cette réponse se termine juste après les deux-points :

{"commande":"A-17","quantite":

Résultat du test de cet exemple avec Réparer JSON :

{"commande":"A-17","quantite":null}

L’outil a ajouté null et une accolade de fermeture. La syntaxe est maintenant valide, mais nous ne connaissons toujours pas la quantité : elle aurait pu être 2, 20 ou un autre nombre. Ce null n’est pas la valeur retrouvée. Nous ne savons pas non plus si l’application accepte les valeurs nulles dans ce champ, ni s’il manque d’autres informations sur la commande.

Demandez à nouveau la réponse complète, ou cherchez la quantité dans la source originale et renseignez le champ. Le résultat ci-dessus vaut pour cet exemple. Si le texte est coupé ailleurs, l’outil peut apporter d’autres modifications ou échouer. Le problème est le même pour une chaîne ou un tableau incomplet : ajouter le délimiteur de fermeture ne restitue pas le contenu perdu.

Votre application attend-elle du texte ou un nombre ?

Ces deux documents ont une syntaxe valide :

{"quantite":"2"}
{"quantite":2}

Le premier contient une chaîne et le second un nombre. Le RFC 8259 distingue ces types de valeurs. Si le contrat de votre application exige un nombre, le premier document ne le respecte pas. Consultez la source avant de corriger : convertir les types sans examen peut modifier les données, par exemple un identifiant "002" dont les zéros font partie de la valeur.

L’outil de réparation ne connaît pas les règles de votre application : les champs obligatoires, les types acceptés ou le nombre d’enregistrements demandé. Ces points restent à vérifier, même si le JSON passe la validation du premier coup.

Vérifications avant d’utiliser la sortie

  • Seules des enveloppes ont-elles été retirées, ou des valeurs, guillemets ou délimiteurs de fermeture ont-ils été ajoutés ?
  • Les champs obligatoires et le nombre attendu d’enregistrements sont-ils toujours présents ?
  • Les identifiants, nombres, booléens et valeurs nulles ont-ils été conservés, avec les types exigés par la destination ?
  • Y a-t-il des avertissements, par exemple sur une possible perte de précision des nombres très grands ou très précis ? Vérifiez leur texte original et la représentation utilisée par votre application.
  • Pouvez-vous justifier chaque modification avec le document complet ou la source ?

Si l’outil annonce une réussite, la sortie a une syntaxe valide ; vérifiez encore les données qu’il a ajoutées. Si le traitement s’arrête à cause d’une limite, lisez le message pour savoir laquelle a été atteinte. Cet échec ne suffit pas à dire que le JSON contient une erreur de syntaxe ou qu’il est impossible à réparer.

Vous pouvez utiliser le résultat après avoir vérifié que les modifications préservent les données et que celles-ci conviennent à votre application. Si une valeur ou un type est incorrect, appuyez-vous sur la source pour le corriger. S’il manque des informations et que vous ne pouvez pas les retrouver, demandez à nouveau les données.

Dans votre prochaine demande, précisez que vous souhaitez uniquement du JSON, avec les champs, leurs types et le nombre d’enregistrements attendus. Vous pourrez ainsi repérer plus facilement les oublis et les écarts en relisant la réponse.
