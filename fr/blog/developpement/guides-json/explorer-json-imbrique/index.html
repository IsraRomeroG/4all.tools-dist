Comment explorer un JSON imbriqué et trouver le chemin d’une valeur

Suivez les objets et les indices des tableaux, reconnaissez les noms littéraux des propriétés et copiez la position exacte d’une valeur dans l’arbre JSON.

Pour trouver une valeur dans un JSON imbriqué, vous pouvez ouvrir les objets et les tableaux jusqu’à l’atteindre. Prenons une commande : nous allons retrouver le code du deuxième article et copier son chemin. L’exemple contient aussi une propriété nommée commande.articles, à distinguer de la propriété articles située dans commande.

Trouver le deuxième article d’une commande

Copiez ce document complet dans le visualiseur d’arbre JSON :

{
  "commande": {
    "articles": [
      {"sku": "L-10", "prix": 12},
      {"sku": "L-11", "prix": 18}
    ],
    "livraison": null
  },
  "commande.articles": {"sku": "LITTERAL"},
  "articles[0]": "ETIQUETTE",
  "extras": []
}

L’objet extérieur constitue la racine du document. Dans commande, le tableau articles contient les deux articles. Les indices commencent à 0 : le deuxième article se trouve donc à l’indice 1. Son code sku est "L-11".

Les objets regroupent des propriétés par nom, tandis que les tableaux conservent une séquence ordonnée de valeurs, comme l’explique la RFC 8259. Pour revoir les types, consultez le guide de découverte de JSON.

Suivre le chemin dans le visualiseur

  1. Collez le document dans Entrée JSON et sélectionnez Explorer le JSON. Le collage seul ne lance pas l’analyse.
  2. L’arbre montre d’abord la racine, dont le chemin est $. Cliquez sur le signe + de cette ligne pour la développer, puis faites de même pour la propriété commande.
  3. Développez articles. Les éléments d’indices 0 et 1 apparaissent. Développez celui d’indice 1.
  4. Sélectionnez sa ligne sku. Vérifiez que le type est une chaîne et que l’aperçu affiche "L-11".
  5. Le chemin sélectionné est $.commande.articles[1].sku. Sélectionnez Copier le chemin sélectionné pour partager cette position.

Pour refermer une branche, cliquez sur son signe −. Au clavier, la flèche droite permet de la développer et la flèche gauche de la réduire.

Pour cet exemple, Valeurs JSON affiche 14 : ce nombre comprend la racine, les conteneurs et les valeurs qu’ils contiennent. Lignes visibles commence à 1 et change lorsque vous développez, réduisez ou changez de page. Il ne représente pas le nombre total de valeurs du document.

Distinguer un chemin d’un nom littéral

Ces parcours mènent à des positions différentes dans le même exemple :

Parcours Chemin affiché par le visualiseur Résultat
commande → articles → indice 1 → sku $.commande.articles[1].sku "L-11"
Propriété racine commande.articles → sku $["commande.articles"].sku "LITTERAL"
Propriété racine articles[0] $["articles[0]"] "ETIQUETTE"
commande → livraison $.commande.livraison null : la propriété existe.
commande → remise Aucune ligne ni aucun chemin sélectionnable. La propriété est absente.
extras $.extras [] : un tableau sans éléments.

Plusieurs champs portent le nom sku : copiez le chemin complet pour préciser celui dont vous parlez. Regardez aussi les trois dernières lignes : livraison existe et vaut null, remise est absente et extras est un tableau vide. Vous ne trouverez donc pas d’élément extras[0] à ouvrir.

Lire et partager le chemin copié

Le visualiseur utilise $ pour la racine, des points pour les noms simples et des crochets pour les indices des tableaux. Les noms spéciaux figurent entre crochets sous forme d’une chaîne entre guillemets doubles. Les guillemets et les barres obliques inverses du nom sont échappés comme dans une chaîne JSON :

Nom littéral d’une propriété à la racine Chemin affiché
a.b $["a.b"]
a"b $["a\"b"]
a\b $["a\\b"]
a/b $["a/b"]

La barre / est conservée ; elle ne sépare pas les niveaux dans cette notation. Copiez le chemin complet plutôt que de le reconstruire en retirant des guillemets ou des échappements. Si la racine était le tableau [{"sku":"L-10"},{"sku":"L-11"}], le deuxième code aurait le chemin $[1].sku. Si le document entier était null, son chemin serait $.

Le chemin copié permet à une autre personne de retrouver la valeur dans le même JSON. Le visualiseur utilise sa propre notation, différente de JSON Pointer. Si vous comptez utiliser ce chemin dans un autre outil, vérifiez d’abord la syntaxe qu’il accepte.

Si vous avez déjà converti le JSON de l’exemple en un objet JavaScript nommé donnees, voici comment accéder aux deux champs sku :

donnees["commande"]["articles"][1]["sku"] // "L-11"
donnees["commande.articles"]["sku"]     // "LITTERAL"

Que vérifier si la valeur n’apparaît pas

Ce que vous observez Vérification ou action
Vous arrivez à "L-10" Vous avez choisi l’indice 0. Le deuxième article se trouve à l’indice 1.
Vous voyez seulement un objet ou un tableau S’il contient des éléments, cliquez sur +. Une branche réduite masque des lignes.
remise n’apparaît pas dans commande Vérifiez le bon objet et toutes ses pages. Cette propriété n’existe pas dans l’exemple.
Vous voyez null ou un conteneur indiqué comme n’ayant pas d’éléments enfants Ce sont des valeurs présentes ; la valeur nulle et les conteneurs vides n’ont pas d’enfants à développer.
Certains éléments d’une liste ne sont pas visibles Chaque page contient au plus 50 lignes. Utilisez Page suivante ou Page précédente.
Un avertissement de limite apparaît Lisez le diagnostic. Pour la limite de 500 lignes visibles, réduisez une autre branche ; pour les limites d’entrée ou d’analyse, réduisez le document.
Le document ne peut pas être analysé Vérifiez sa syntaxe avec le formateur et validateur JSON.

Le visualiseur exige du JSON strict et rejette les commentaires, les virgules finales et les noms dupliqués dans un même objet. Répéter sku dans des objets différents, comme dans cet exemple, est permis.

Pour les documents volumineux, gardez à l’esprit les limites du visualiseur : 1 000 000 d’unités de code UTF-16, 200 niveaux d’imbrication et 100 000 valeurs JSON. L’analyse peut aussi s’arrêter si elle dépasse la durée ou la quantité de travail autorisées pour le traitement. Dans ce cas, essayez avec une plus petite partie du document pour retrouver le champ recherché.

Les aperçus affichent jusqu’à 120 unités de code UTF-16. Si un texte est coupé, consultez le JSON d’origine pour lire la valeur complète.

Quand utiliser une requête JSONPath

Dans cet exemple, nous cherchions un seul sku. Pour récupérer les codes de tous les articles à la fois, utilisez un outil capable d’exécuter des requêtes JSONPath. Le visualiseur d’arbre n’exécute pas ces requêtes et ne permet pas de rechercher ou de modifier le contenu du document.
