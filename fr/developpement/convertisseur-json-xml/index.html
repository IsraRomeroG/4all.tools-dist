Convertissez JSON et XML localement

Convertissez JSON strict et un sous-ensemble de données XML 1.0 localement, avec racines explicites, attributs, éléments répétés et avertissements de pertes.

Espace de travail de l’outil

XML perd les types JSON et l’intention des tableaux à un élément. Aucun aller-retour universel : null et objet vide peuvent devenir le même élément vide. XML → JSON conserve les chaînes et la vraie racine.

Utilisez @attributes pour les attributs chaînes et #text pour les feuilles. Les tableaux donnent des éléments répétés. Noms ASCII ; pas d’espaces de noms ni de contenu mixte. Lire l’explication complète du modèle

Sens de conversion
Options de conversion

Nomme seulement les éléments si le contenu racine est un tableau ; les tableaux de propriété gardent leur nom.

Texte et attributs XML restent des chaînes, y compris 00123. La racine est conservée ; aucun type JSON n’est déduit.

Collez du texte ou choisissez un fichier local UTF-8. Cliquez sur Convertir pour le traiter.

Prêt à recevoir du texte.

Web Workers indisponibles. La conversion ne peut pas fonctionner ici ; l’entrée reste locale.

Erreurs et avertissements de conversion

    Certains détails ont été omis ; la cause de l’erreur est conservée.

    Copie et téléchargement utilisent la sortie actuelle complète.

    Modèle et sous-ensemble pris en charge

    Utiliser la propriété racine unique exige un objet JSON avec une propriété : son nom devient la racine XML. Envelopper avec un nom racine ajoute la racine choisie au contenu. Un tableau racine utilise le nom d’élément ; les tableaux de propriété répètent leur nom. Tableaux non vides et sans imbrication directe. @attributes est un objet de valeurs chaînes ; #text est une chaîne permise seulement sans enfants, même vide ou composée d’espaces. Les attributs XML reviennent sous @attributes ; une feuille avec attributs inclut #text. Les enfants contigus de même nom deviennent des tableaux ; les groupes entrelacés sont rejetés pour garder l’ordre. Une feuille XML vide sans attributs devient une chaîne JSON vide ; avec attributs elle garde #text="" dans un objet. Nombres et booléens perdent le type ; null, objets vides et tableaux uniques perdent l’intention. Sous-ensemble XML 1.0 : noms ASCII de 1–64 caractères, sans préfixe xml, espaces de noms, DTD ni instructions de traitement. Seules entités prédéfinies et références numériques sont décodées une fois. Commentaires, délimiteurs CDATA, déclaration et espaces de présentation sont omis avec avertissements. Espaces des feuilles conservés ; fins de ligne XML et espaces littéraux d’attributs normalisés. Aucune déduction de types ni réparation automatique.

    Limites

    JSON → XML : choisir explicitement la racine

    Collez du JSON strict ou chargez un fichier local .json, choisissez JSON → XML, puis Convertir. Par défaut, Utiliser la propriété racine unique (document) exige un objet contenant exactement une propriété ordinaire. Envelopper avec un nom racine (wrap) ajoute la racine choisie, initialement root ; aucune racine existante n’est extraite automatiquement. Un tableau racine utilise le nom d’élément, initialement item ; ce réglage ne renomme pas les tableaux sous propriétés. Choisissez sortie compacte ou formatée et 2 ou 4 espaces. La sortie compacte garde l’indentation mémorisée sans ajouter d’espaces de présentation.

    {"catalog":{"@attributes":{"id":"00123"},"item":[{"@attributes":{"code":"a"},"#text":"uno & dos"},{"@attributes":{"code":"b"},"#text":"tres"}]}}
    <catalog id="00123"><item code="a">uno &amp; dos</item><item code="b">tres</item></catalog>

    @attributes est un objet dont les valeurs sont uniquement des chaînes. #text doit être une chaîne dans une feuille sans enfants, même vide ou composée d’espaces. Les propriétés ordinaires créent des enfants dans l’ordre source ; les tableaux répètent le nom de cette propriété. Un objet @attributes: {} vide est omis avec avertissement ; une valeur vide d’attribut, comme id="", est conservée. Un objet contenant seulement #text perd son enveloppe JSON. Le tableau racine ["a","b"], avec wrap racine root et élément item, donne <root><item>a</item><item>b</item></root>. Les tableaux doivent être non vides et ne peuvent être directement imbriqués ; chaque élément hétérogène est vérifié et tout élément non représentable fait échouer la conversion entière.

    XML → JSON : chaînes et racine réelle conservées

    Collez XML ou chargez un .xml, choisissez XML → JSON, sélectionnez 2 ou 4 espaces et convertissez. La racine réelle reste toujours une propriété JSON. Texte et attributs restent des chaînes : 00123, true et les dates apparentes ne sont pas inférés comme nombres, booléens ou dates. Les attributs apparaissent d’abord sous @attributes ; une feuille avec attributs inclut toujours #text, même "". Une feuille sans attributs devient une chaîne. Les frères consécutifs de même nom forment des tableaux ; des groupes entrelacés comme a/b/a sont rejetés car leur regroupement changerait l’ordre.

    Les nombres et booléens deviennent du texte XML et reviennent comme chaînes, avec avertissements de perte de type. Les lexèmes 9007199254740993, 1.2300 et -0 sont conservés ; l’avertissement de précision numérique diffère de la perte du type JSON. Un dépassement numérique non fini échoue. null et objet vide donnent le même élément vide et reviennent comme "" ; un tableau à un élément ne retrouve pas son intention de tableau. Un tableau racine revient comme objet d’enfants item répétés, sans inférer un tableau racine. Consultez les comptes et premiers emplacements des avertissements. Aucun round-trip universel ni réparation automatique.

    Un modèle de données XML 1.0 limité

    Noms de 1–64 caractères ASCII : lettre ou soulignement initial, puis lettres, chiffres, soulignement, tiret ou point. Préfixe xml quelle que soit la casse, syntaxe de namespace et noms dangereux liés aux prototypes sont rejetés sans alias ni renommage. Toute clé JSON n’est pas un nom XML. JSON strict rejette doublons, commentaires et extensions. XML exige une racine complète, fermetures respectant la casse et attributs distincts.

    Namespaces, DTD/DOCTYPE, déclarations ENTITY, instructions de traitement (PI), contenu mixte texte/enfants, frères entrelacés, entités inconnues et XML mal formé sont rejetés avant le parseur externe. Pas de prise en charge XML général, HTML, XSD, XPath, XInclude ou XSLT. Seules les cinq entités prédéfinies et références numériques valides sont décodées une fois ; &amp;lt; devient texte &lt;, pas <. Le texte CDATA rejoint le texte des feuilles ; commentaires, délimiteurs CDATA et déclaration XML sont omis avec avertissements.

    CRLF et CR XML deviennent LF. TAB/LF/CR littéraux des attributs deviennent des espaces ; les références numériques conservent ces valeurs. Les espaces de présentation entre enfants sont omis avec avertissement ; les espaces des feuilles restent données. Une feuille XML vide, pas un document vide, devient une chaîne JSON vide. Valeur sémantique et représentation textuelle diffèrent : déclaration, guillemets, commentaires et mise en forme ne sont pas reconstruits.

    UTF-8, limites et export local complet

    Fichiers UTF-8 strict ; extension/MIME aident à choisir sans prouver la validité. Un BOM UTF-8 initial est retiré avec avertissement ; un second initial est rejeté. CRLF/CR originaux de l’éditeur ou fichier restent dans la source conservée et les coordonnées. XML sort sans BOM/déclaration et avec LF final ; JSON suit l’indentation sans LF final forcé. Téléchargements : converted.xml (application/xml) ou converted.json (application/json), charset UTF-8.

    Entrée : 1 000 000 unités UTF-16 et 2 000 000 octets UTF-8 ; un fichier jusqu’à 2 000 000 octets. Sortie : 2 000 000 unités et 4 000 000 octets. JSON source : 50 000 nœuds et 100 niveaux de conteneurs ; XML : 50 000 éléments, 50 000 attributs, 100 par élément, 200 000 tokens et profondeur 40. Données décodées : 1 000 000 unités ; JSON résultat : 100 000 nœuds/profondeur 100. Travail propre : 8 000 000 unités ; analyse et écriture JSON : 1 000 000 chacun. Détails diagnostics 20, familles d’avertissements 13, texte d’emplacement 4 096 et métadonnées diagnostics 16 384 unités. Toutes les limites s’appliquent ensemble sans mesurer toute l’activité du processeur. Délai de conversion : 8 000 ms.

    Aperçu en lecture seule : jusqu’à 50 000 unités UTF-16 sans couper une paire d’unités d’un caractère supplémentaire. Copier/télécharger utilisent toujours la sortie complète actuelle ; un échec du presse-papiers propose une action explicite de copie manuelle complète. Un processus local annulable (Worker) convertit sans transmettre le document, le conserver dans le stockage du navigateur ni placer son contenu dans une URL. Édition, mode/options, exemple, effacer ou chargement invalident sortie/export précédents. Erreur, limite, annulation et délai dépassé ne publient jamais de résultat partiel. Sans JavaScript ou processus local disponible, conversion indisponible.
