Affichez un tableau JSON et exportez Markdown

Présentez un tableau d’objets JSON sous forme de table. Choisissez les colonnes et les lignes, puis exportez le Markdown.

Espace de travail de l’outil

Tableau JSON / JSON vers Markdown

Activez JavaScript pour utiliser cet outil local.

Choisissez explicitement un tableau d’objets. Chaînes et en-têtes gardent les guillemets JSON ; les sauts de ligne sont échappés. ∅ désigne une propriété absente, différente de null et "". Objets et tableaux apparaissent en JSON compact ; les colonnes gardent les clés littérales et l’ordre source.

Le document est traité localement dans votre navigateur. L’entrée n’est ni envoyée, ni chargée à distance, ni enregistrée.

Fichier : 4000000 octets ; entrée : 1000000 unités UTF-16 ; profondeur : 200 ; nœuds : 100000 ; lignes : 20000 ; colonnes découvertes : 200 ; positions de cellules incluses : 75000.

Lignes à inclure

Texte de cellule : 10000 ; en-têtes : 20000 ; ligne : 100000 ; tableau : 1000000 ; Markdown : 2000000 unités UTF-16. Tous les maxima ne sont pas acceptés simultanément. Choisissez moins de colonnes ou les N premières lignes pour réduire la sortie.

    Colonnes dans l’ordre d’exportation

      La taille de page ne change que les lignes visibles. Markdown exporte toutes les lignes incluses.

      La largeur ou le texte a réduit cette page par rapport à la taille choisie.

      Tableau JSON sélectionné

      Markdown exporte toutes les lignes incluses pour les tableaux GitHub Flavored Markdown. La ponctuation ASCII devient des entités numériques pour préserver le texte. Un lecteur Markdown peut transformer les URL ou les adresses e-mail en liens cliquables. La source peut être plus longue que le tableau visible. Markdown n’est pas un format JSON réversible.

      Le presse-papiers est indisponible ou refusé. Sélectionnez et copiez tout le Markdown dans le champ de sortie ou réessayez Copier.

      Choisir les données à présenter

      Collez du JSON strict ou ouvrez un fichier .json UTF-8, puis cliquez sur Analyser les tableaux. Sélectionnez le tableau souhaité, y compris $ si le document est lui-même un tableau, puis cliquez sur Inspecter les colonnes. Chaque élément doit être un objet, même si vous ne comptez exporter que les premières lignes.

      L’outil recherche les colonnes dans tout le tableau, y compris les propriétés qui n’apparaissent qu’à la fin. Sélectionnez-en au moins une et utilisez Monter/Descendre pour les ordonner. Les noms sont pris tels quels : un point dans une clé ne désigne pas un chemin imbriqué. Les objets et tableaux imbriqués restent dans une seule cellule.

      Un document sans tableau n’a pas de données à convertir. Un tableau vide [], ou contenant uniquement des objets vides, n’a pas de colonnes. Les commentaires, JSONC, JSON5 et clés dupliquées sont refusés.

      Valeurs absentes, null et chaînes vides

      [{"id":"00123","name":"Ana"},{"name":"Beto","active":true}]

      Cet exemple produit les colonnes id, name et active. La première ligne contient "00123", "Ana" et ∅ ; la seconde, ∅, "Beto" et true.

      Les symboles distinguent trois cas : ∅ indique une propriété absente, null une valeur nulle explicite et "" une chaîne vide. Les chaînes et les en-têtes gardent leurs guillemets JSON. Les sauts de ligne apparaissent sous forme d’échappements JSON et les valeurs imbriquées utilisent du JSON compact.

      Les nombres conservent leur écriture, notamment 1.0, 1e0, -0 et 9007199254740993. Un avertissement de précision ne signifie pas que le texte affiché a été arrondi ; un nombre hors de la plage acceptée, comme 1e999, est refusé.

      Exporter les lignes utiles

      Choisissez toutes les lignes ou les N premières, puis cliquez sur Préparer le tableau. N doit être un entier positif. Ce choix détermine l’exportation ; changer de page ne le modifie pas. Les pages affichent jusqu’à 10, 25 ou 50 lignes, et moins lorsque les cellules contiennent beaucoup de texte.

      Cliquez sur Générer Markdown pour créer une table compatible avec GitHub Flavored Markdown. Les caractères susceptibles d’être interprétés comme de la mise en forme sont encodés : une barre verticale devient &#124; et les guillemets deviennent &#34;. Le HTML, les images et le Markdown présents dans les données restent ainsi du texte. Un lecteur Markdown peut toutefois transformer les URL ou adresses e-mail en liens.

      La copie et le téléchargement incluent toutes les lignes sélectionnées. Le fichier est nommé json-table.md, en UTF-8 sans BOM, avec des fins de ligne LF et un saut final. Si le presse-papiers échoue, utilisez la copie manuelle. Vérifiez le résultat dans le lecteur prévu : les dialectes diffèrent et la table ne permet pas de reconstruire le JSON d’origine.

      Limites et traitement local

      Limite Maximum
      Fichier 4 000 000 octets
      Entrée 1 000 000 unités UTF-16
      Conteneurs imbriqués / valeurs JSON 200 niveaux / 100 000
      Lignes source / colonnes 20 000 / 200
      Positions de cellules sélectionnées 75 000
      Texte par cellule 10 000 unités UTF-16
      Table complète / Markdown 1 000 000 / 2 000 000 unités UTF-16

      Des en-têtes longs, des lignes volumineuses ou des structures complexes peuvent atteindre d’autres limites de traitement plus tôt. En cas d’erreur, l’outil ne coupe pas les cellules et ne fournit pas de table partielle. Si le Markdown dépasse sa limite, la table préparée reste disponible, mais aucun export partiel n’est proposé.

      Le traitement utilise un Worker local et nécessite JavaScript. L’entrée et la sortie ne sont ni envoyées ni enregistrées. Les fichiers doivent utiliser UTF-8 ; un BOM initial est retiré avec un avertissement, tandis qu’un second est refusé.

      Après avoir changé l’entrée, le tableau, les colonnes ou la sélection de lignes, préparez à nouveau la table. L’annulation conserve l’entrée ; une nouvelle tentative relance son analyse.
