Affichez un tableau JSON et exportez Markdown

Choisissez un tableau d’objets, sélectionnez des colonnes littérales et exportez une table Markdown GFM sûre localement dans votre navigateur.

Espace de travail de l’outil

Tableau JSON / JSON vers Markdown

Activez JavaScript pour utiliser cet outil local.

Choisissez explicitement un tableau d’objets. Chaînes et en-têtes gardent les guillemets JSON ; les sauts de ligne sont échappés. ∅ désigne une propriété absente, différente de null et "". Objets et tableaux apparaissent en JSON compact ; les colonnes gardent les clés littérales et l’ordre source.

Le document est traité localement dans votre navigateur. L’entrée n’est ni envoyée, ni chargée à distance, ni enregistrée.

Fichier : 4000000 octets ; entrée : 1000000 unités UTF-16 ; profondeur : 200 ; nœuds : 100000 ; lignes : 20000 ; colonnes découvertes : 200 ; positions de cellules incluses : 75000.

Lignes à inclure

Texte de cellule : 10000 ; en-têtes : 20000 ; ligne : 100000 ; tableau : 1000000 ; Markdown : 2000000 unités UTF-16. Tous les maxima ne sont pas acceptés simultanément. Choisissez moins de colonnes ou les N premières lignes pour réduire la sortie.

      Choisir le tableau et les colonnes

      Collez du JSON strict ou ouvrez un fichier .json UTF-8, puis cliquez sur Analyser les tableaux. Choisissez explicitement un tableau source, même à la racine $, puis cliquez sur Inspecter les colonnes. Les tableaux sont présentés par chemins littéraux et pages. Chaque ligne doit être un objet, même celles omises ensuite. Les clés décodées dupliquées, JSONC, JSON5 et UTF-8 invalide sont refusés. Un JSON valide sans tableau possède un état spécifique ; [] et les tableaux d’objets vides n’ont aucune colonne.

      L’union des colonnes couvre toutes les lignes dans l’ordre source, y compris les clés tardives. Choisissez un sous-ensemble non vide et utilisez Monter/Descendre pour l’ordre d’exportation. Clés vides, numériques, points, crochets, Unicode et __proto__ restent littéraux. [{"":null,"10":1,"2":2},{"2":3,"late":true}] découvre "", "10", "2", "late" dans cet ordre. Les objets imbriqués sont des cellules, sans aplatissement.

      Les mêmes cellules dans les deux sorties

      [{"id":"00123","name":"Ana"},{"name":"Beto","active":true}]

      Les colonnes par défaut sont id, name, active. La première ligne affiche "00123", "Ana", ∅ ; la seconde, ∅, "Beto", true. Chaînes et en-têtes conservent les guillemets JSON. Une absence est ∅, null est null et une chaîne vide est "". Sauts de ligne et contrôles utilisent des échappements JSON. Les objets et tableaux sont du JSON compact dans l’ordre source. Les nombres gardent 1.0, 1e0, -0 et 9007199254740993, même dans les cellules imbriquées. L’avertissement de précision décrit l’approximation interne du parser ; un dépassement tel que 1e999 est refusé.

      Choisissez toutes les lignes ou les N premières, avec N entier positif. Cette omission volontaire est annoncée séparément ; l’union couvre toujours tout le tableau. Préparer le tableau crée le résultat choisi. Les pages de 10/25/50 lignes indiquent le vrai intervalle et peuvent être réduites par la largeur ou le texte. La pagination ne change jamais les lignes exportées.

      Générer, copier et télécharger Markdown

      Cliquez sur Générer Markdown pour exporter toutes les lignes incluses depuis les mêmes cellules préparées. La cible est GitHub Flavored Markdown avec tableaux et entités numériques. La ponctuation ASCII est volontairement codée : un pipe de données devient &#124; et les guillemets &#34;. La syntaxe HTML, des images et Markdown est échappée en préservant le texte. Un lecteur Markdown peut transformer les URL ou les adresses e-mail en liens cliquables après décodage des entités. Le tableau local affiche uniquement du texte. Les échappements JSON restent visibles. La source Markdown peut être plus longue que le tableau affiché. L’outil n’exécute aucun moteur de rendu Markdown.

      Copier fournit la sortie complète ; si le presse-papiers échoue, sélectionnez le champ en lecture seule et copiez manuellement. Le téléchargement fournit le même texte sous json-table.md, UTF-8 sans BOM, avec fins de ligne LF et un LF final. Une limite d’expansion Markdown conserve le tableau valide sans exportation partielle. Markdown n’est pas du JSON réversible et aucun support universel des dialectes n’est promis.

      Traitement local et limites

      JavaScript et un Worker local sont nécessaires. Entrée et sortie ne sont ni envoyées ni enregistrées dans le stockage, les logs ou les URLs. Les outils associés s’ouvrent sans transfert de données. Modifier entrée, tableau, colonnes ou limite de lignes invalide les résultats ; changer de page conserve l’exportation. Annuler termine le Worker ; réessayer analyse la source actuelle. Un fichier refusé conserve le texte précédent. Le retrait d’un BOM initial est signalé ; un second BOM initial est invalide.

      Fichier : 4 000 000 octets ; entrée : 1 000 000 unités UTF-16 ; profondeur : 200 ; nœuds : 100 000 ; lignes : 20 000 ; union : 200 colonnes ; clés : 1 000 unités ; positions incluses : 75 000. Texte de cellule : 10 000 ; en-têtes : 20 000 ; ligne : 100 000 ; tableau : 1 000 000 ; Markdown : 2 000 000 unités. Une page monte au maximum 50 lignes, 2 500 cellules et 200 000 unités de texte. Analyse et travail structurel ont aussi des budgets stricts : tous les maxima ne sont pas acceptés simultanément. Les limites échouent sans tableau partiel ni cellule tronquée. Il n’y a ni édition, filtres, tri des lignes, schéma manuel, flatten, réparation, CSV supplémentaire, XLSX ou export HTML.
