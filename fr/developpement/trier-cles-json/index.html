Triez les clés des objets JSON dans votre navigateur

Triez les clés JSON strictes dans l’ordre croissant ou décroissant, récursivement ou à la racine, en conservant tableaux et tokens numériques originaux localement.

Espace de travail de l’outil

Trier les clés JSON

Activez JavaScript pour trier JSON localement dans votre navigateur.

Les clés suivent l’ordre textuel UTF-16 : "10" précède "2" dans l’ordre croissant. Ignorer la casse convertit uniquement A–Z ; É et é restent distincts. Racine uniquement laisse les objets d’un tableau racine sans tri. Les tableaux gardent les positions de leurs éléments. Les espaces et échappements des chaînes peuvent être normalisés.

Fichier : 4 000 000 octets ; entrée : 1 000 000 unités UTF-16 ; profondeur : 200 conteneurs ; nœuds : 100 000 ; sortie : 2 000 000 unités UTF-16.

Options de tri

Budgets : 1 000 000 unités d’analyse, 1 000 000 de sérialisation et 1 000 000 de tri. Les préfixes longs ou l’indentation peuvent épuiser un budget avant la limite de taille. Ces maxima ne sont pas tous garantis simultanément.

Le traitement reste dans votre navigateur. Aucun envoi, URL distante ou document enregistré. Ce n’est pas une canonicalisation cryptographique ni JCS.

{"z":{"2":"dos","10":"diez"},"a":[{"b":2,"a":1}]}
Options de tri

Prêt à trier.

    Les diagnostics sont incomplets : l’inspection s’est arrêtée ou le budget a été atteint.

    Sélectionnez et copiez le texte complet, ou appuyez sur Copier à nouveau avec une nouvelle activation du navigateur.

    Lancez le tri explicitement

    Collez du JSON strict ou ouvrez un fichier .json UTF-8. Appuyez sur Trier les clés pour produire un résultat séparé. Les valeurs par défaut sont croissant, sensible à la casse, récursif et deux espaces avec LF. Quatre espaces, une tabulation et la sortie minifiée sont aussi disponibles. Charger un exemple ou changer les options ne lance pas le traitement.

    L’exemple partagé est :

    {"z":{"2":"dos","10":"diez"},"a":[{"b":2,"a":1}]}

    Avec les options par défaut :

    {
  "a": [
    {
      "a": 1,
      "b": 2
    }
  ],
  "z": {
    "10": "diez",
    "2": "dos"
  }
}

    Ordre textuel, casse et portée

    Les clés décodées sont comparées ordinalement par unités UTF-16. Les clés numériques sont du texte : "10" précède "2" dans l’ordre croissant. L’ordre sensible à la casse est A,B,a,b ; Ignorer la casse A–Z donne A,a,B,b, avec la clé originale pour départager. Décroissant inverse le résultat entier, y compris les égalités départagées. Les accents ne sont pas convertis : É et é restent distincts et Unicode n’est pas normalisé.

    Le mode récursif trie tous les objets, même dans les tableaux. Objet racine uniquement conserve la séquence source des objets descendants ; une racine tableau ne trie aucun de ses objets. Les tableaux conservent leur longueur et les positions des éléments. Les racines primitives, objets et tableaux vides sont valides. Sans objet admissible, le formatage s’applique et un avis informatif apparaît.

    Conservez les valeurs et rejetez les ambiguïtés

    Chaînes, clés décodées, booléens, null et structures conservent leurs valeurs. Les tokens originaux 9007199254740993, 0.10000000000000001, -0 et 1E+02 sont conservés exactement. L’avertissement de précision décrit la valeur interne approximative du parser, pas un arrondi de la sortie. Les nombres hors de la plage du parser, comme 1e400, échouent explicitement.

    {"a":1,"\u0061":2} échoue car la clé décodée est dupliquée ; aucune occurrence n’est remplacée silencieusement. Commentaires, JSONC, JSON5 et JSON mal formé sont rejetés. Une signature BOM initiale est retirée avec avis ; une seconde signature est une erreur de syntaxe. La sortie est reformatée avec LF, sans BOM ni saut final ; les espaces et l’écriture exacte des échappements ne sont pas conservés. Ce n’est pas JCS ni une canonicalisation cryptographique pour signatures.

    Limites, exportations complètes et traitement local

    Les fichiers acceptent jusqu’à 4 000 000 octets originaux. L’entrée accepte 1 000 000 unités UTF-16, la profondeur 200 conteneurs, les nœuds source 100 000 et la sortie 2 000 000 unités UTF-16. Analyse, sérialisation et tri ont chacun un budget de 1 000 000 unités de travail ; préfixes longs ou indentation profonde peuvent l’épuiser avant la limite de taille. Ces maxima ne sont pas garantis simultanément. L’opération dispose de 15 secondes et la récupération de la sortie de 5 secondes. Au maximum 100 diagnostics et un aperçu de 20 000 unités sont affichés.

    L’aperçu tronqué peut être un JSON incomplet. Tout copier et Télécharger JSON récupèrent le résultat complet avec tous ses chiffres. Si le presse-papiers échoue, utilisez le champ complet pour une copie manuelle ou Copier à nouveau. Le téléchargement utilise json-sorted.json, UTF-8 et le type MIME JSON.

    Tout est traité dans le navigateur, sans envoi, URL distante ou stockage de documents. Annuler conserve la source et les options. Modifier le texte, choisir un fichier, changer les options ou effacer invalide les anciens résultats et exports. Effacer conserve les options choisies. JavaScript et un navigateur prenant en charge les Workers sont nécessaires.

    Outils associés

    • Formateur et Validateur JSON

      Formatez, embellissez et validez du JSON en ligne. Détectez les erreurs de syntaxe et rendez les données JSON plus lisibles.

    • Comparateur JSON

      Comparez deux documents JSON stricts selon leurs valeurs. Consultez les ajouts, suppressions et modifications avec des diagnostics localisés et des aperçus limités.

    • Explorateur d’arbre JSON

      Explorez du JSON strict dans un arbre extensible et limité. Inspectez les types, parcourez les grands tableaux par pages et copiez un chemin JSON dans votre navigateur.
