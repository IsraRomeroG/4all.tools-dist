Convertir JSON et CSV dans votre navigateur

Convertissez des tableaux d’objets JSON en CSV ou inspectez les en-têtes CSV et transformez les lignes en JSON avec des choix explicites de types et de lignes irrégulières.

Espace de travail de l’outil

Convertir JSON en CSV et CSV en JSON

Sens de conversion

Choisissez un tableau d’objets après inspection. L’entrée reste intacte.

Exemple reproductible

{
  "people": [
    { "name": "Ada", "active": true, "score": 42 },
    { "name": "Grace", "score": null }
  ]
}

          Convertir des tableaux d’objets JSON en CSV
          

          Collez un document JSON ou chargez un fichier local .json, puis choisissez Inspecter les tableaux. Les chemins et nombres de lignes s’affichent par pages de 200 tableaux au maximum. Choisissez un tableau pour inspecter l’union complète des clés de ses objets. Les clés apparaissant seulement dans des lignes ultérieures sont incluses :
          

          {"personnes":[{"nom":"Ada"},{"nom":"Grace","ville":"Paris"}]}
          

          Réorganisez les colonnes avec les boutons Monter et Descendre. Un tableau vide n’a aucune clé à inspecter ; ajoutez des noms de colonne uniques avant la conversion. Choisissez la virgule, le point-virgule ou la tabulation comme séparateur, LF ou CRLF comme fin d’enregistrement et l’ajout éventuel d’un BOM UTF-8.
          

          Le CSV ne possède pas les types JSON. Les nombres, booléens, null, propriétés absentes et chaînes vides peuvent devenir des cellules vides ou textuelles indifférenciables. Une exportation à une colonne conserve la dernière cellule vide de façon explicite :
          

          nom
Ada
""
          

          Inspecter le CSV avant de choisir les types JSON
          

          Collez du texte CSV ou chargez un fichier local .csv ; choisissez le séparateur et la politique des champs supplémentaires avant Inspecter le CSV. Les en-têtes doivent être uniques et non vides. Après l’inspection, choisissez un type pour chaque en-tête, y compris ceux qui ont été générés. Aucune inférence n’est faite : chaque colonne reste une chaîne sauf si vous choisissez explicitement nombre ou booléen.
          

          Par exemple, 00123 reste la chaîne "00123" par défaut. Une ligne courte omet la propriété manquante par défaut. Une ligne longue échoue avec la politique Rejeter ; Étendre ajoute des noms tels que column_3 pour les champs supplémentaires. Les cellules vides peuvent rester des chaînes, devenir null ou être omises. Vous pouvez aussi choisir si les lignes courtes omettent ou complètent les valeurs manquantes.
          

          Le lecteur CSV accepte les champs entre guillemets, les guillemets doublés échappés, les séparateurs entre guillemets et les cellules multiligne citées. Il accepte LF et CRLF. Une signature BOM UTF-8 initiale est retirée pour l’analyse et signalée.
          

          Protection des formules et texte exact
          

          Par défaut, une apostrophe est ajoutée devant le texte CSV commençant par =, +, - ou @ afin de réduire le risque d’exécution d’une formule dans un tableur. Cela peut modifier le texte exact. Désactivez cette protection pour exporter le texte exact. Si la protection rend deux en-têtes identiques, le convertisseur signale HEADER_PROTECTION_COLLISION et ne crée aucun résultat ; choisissez le texte exact ou modifiez les en-têtes source avant de réessayer.
          

          La conversion JSON vers CSV peut aussi signaler une perte d’information de type JSON ou de précision numérique. Consultez ces avertissements si le CSV sert de données et pas seulement d’affichage dans un tableur.
          

          Limites du navigateur et confidentialité
          

          Les limites de 4 Mio par fichier, 1 000 000 d’unités UTF-16 en entrée, 2 000 000 en sortie, 20 000 lignes de données, 200 colonnes, 100 000 unités par cellule, 75 000 positions de cellules de données et 20 000 unités d’aperçu maintiennent le traitement borné. L’aperçu ne contient pas toute la sortie ; Tout copier et Télécharger demandent le résultat complet conservé uniquement après activation du bouton correspondant. Un aperçu tronqué n’est jamais copié comme s’il était complet.
          

          L’analyse et la conversion s’exécutent dans un Web Worker local. L’entrée n’est pas envoyée à un serveur, placée dans l’URL ou enregistrée dans le stockage du navigateur. Les erreurs indiquent les chemins JSON ou, pour le CSV, la ligne logique, le champ et la ligne/colonne physiques lorsqu’ils sont disponibles. Modifier l’entrée active efface son résultat ; annuler arrête l’opération du Worker sans modifier l’entrée.
