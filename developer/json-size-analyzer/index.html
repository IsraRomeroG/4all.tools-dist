    Analyze your current JSON text

    Paste one strict JSON document or open a UTF-8 .json file, then press Analyze JSON. Primitive roots, empty strings, null, {} and [] are valid. Decoded duplicate keys are rejected, including {“a”:1,“\u0061”:2}. JSONC, JSON5 and repair are outside this tool. JavaScript and a local Worker are required. Processing is local in this browser tab: input and reports are never uploaded or saved in storage, logs or URLs. Related tools open without transferring your document.

    Bytes, length and conservative minification

    Original bytes encode the current editor text as UTF-8, including spaces and an initial BOM. This is the adopted text, which the editor may normalize for line endings; it is not a promise of equality with the original file size. Length counts UTF-16 code units, not visible characters. KiB and MiB use base 1024.

    Minification removes only SP, TAB, LF and CR outside strings, plus one allowed initial BOM. It preserves key order, whitespace inside strings, Unicode escapes and number spellings such as 1.0, 1e0, -0 and 9007199254740993. It does not serialize the semantic JavaScript value. A precision warning describes an internal approximation; bytes and node counts do not round that number. Overflow such as 1e999 is rejected. A second initial BOM is invalid.

    The text {“é”:“😀”} measures 10 UTF-16 units and 13 UTF-8 bytes. The equivalent strings “\u00E9” and “é” occupy different source sizes because escapes stay as written. An escaped unpaired surrogate stays as escape text; TextEncoder replaces literal isolated surrogates according to its encoding rules, while syntax remains governed by the strict parser. No Unicode normalization occurs.

    Try the exact example

    {"a":[null,{"b":true}],"c":"x"}

    The example has 31 original and minified bytes, 31 original and minified UTF-16 units, zero savings, 6 value nodes, 3 keys, maximum path depth 3 and maximum container depth 3. Its types are 2 objects, 1 array, 1 null, 1 boolean, 1 string and 0 numbers. A formatted variant can save whitespace; a successful analysis can also save zero bytes.

    Nodes, depth and bounded details

    Every value node counts once, including the root and empty containers. Keys count object members, not array indices or string nodes. Type percentages use the count of all nodes, not bytes; zeros remain visible and rounded percentages may not sum to 100%.

    Path depth counts properties and indices from root 0. Container depth counts objects and arrays along a chain: container root 1, primitive root 0. Largest arrays rank by direct element count, not subtree bytes. Deepest paths rank all nodes by segments, not only leaves. Ties use source preorder, including numeric keys in textual order. Each list retains up to 20 rows, with eligible, shown and omitted counts. Global metrics always remain complete. The example array is $.a with 2 elements; deepest paths start $.a[1].b, $.a[0], $.a[1].

    Copy path copies the full path; manual copying is available when clipboard fails. Locate in input selects the original whole value, including containers. Back to result restores focus. Editing, loading a file/example or clearing invalidates the report and its actions. Cancel terminates the Worker and preserves input; a rejected file preserves previous text but does not restore a report.

    Limits and exclusions

    Files allow 4,000,000 bytes; current text 1,000,000 UTF-16 units and 4,000,000 UTF-8 bytes; container depth 200; nodes 100,000; diagnostics 100. Parsing allows 1,000,000 work units, lexical measurement 1,000,000 units, analysis 100,000 visits and both rankings together 4,000,000 comparisons. Each full path allows 10,000 UTF-16 units and both lists together 400,000. At most 40 detail rows mount in the interface. Timeout is 15,000 ms, including Worker startup. Path/work limits can fail even within size/node limits; hard failures have no partial report. Detail omission is successful bounded selection.

    Sizes describe UTF-8 source encoding, not gzip/Brotli, HTTP traffic, JavaScript RAM or model tokens. There is no subtree size attribution, treemap, minified JSON download, report export or document transfer. Strict UTF-8 files preserve an initial BOM for measurement; its removal is visibly reported and its three bytes count as savings.
