    Model and supported subset

    Use the single root property requires a JSON object with exactly one property: its name becomes the XML root. Wrap with a root name adds the chosen root around the content. A root array uses the item name; property arrays repeat their own names. Arrays must be nonempty and cannot be directly nested. @attributes is an object of string values; #text is a string allowed only without child elements, including empty or whitespace text. XML attributes return under @attributes and an attributed leaf includes #text. Contiguous same-name children become arrays; interleaved groups are rejected to preserve order. An empty XML leaf without attributes becomes an empty JSON string; a leaf with attributes keeps #text="" inside an object. Numbers and booleans lose type; null, empty objects and singleton arrays lose intent. XML 1.0 data subset: ASCII names of 1–64 characters, no xml prefix, namespaces, DTD or processing instructions. Only predefined entities and numeric references are decoded once. Comments, CDATA delimiters, declarations and presentation whitespace are omitted with notices. Leaf spaces are retained; XML line endings and literal attribute whitespace normalize. There is no automatic type inference or repair.

    JSON → XML: choose the root explicitly

    Paste strict JSON or load one local .json file, choose JSON → XML, then press Convert. The default Use the single root property (document) requires an object with exactly one ordinary property. Wrap with a root name (wrap) adds the chosen root, initially root; it never extracts an existing root automatically. A root array uses the item name, initially item; this setting does not rename arrays under properties. Choose compact or pretty output and 2 or 4 spaces. Compact keeps the saved indentation setting without adding presentation whitespace.

    {"catalog":{"@attributes":{"id":"00123"},"item":[{"@attributes":{"code":"a"},"#text":"uno & dos"},{"@attributes":{"code":"b"},"#text":"tres"}]}}
    <catalog id="00123"><item code="a">uno &amp; dos</item><item code="b">tres</item></catalog>

    @attributes is an object whose values must be strings. #text must be a string in a leaf without child elements, even when empty or whitespace. Ordinary properties create children in source order; arrays repeat that property’s element name. An empty @attributes: {} object is omitted with a notice; an empty attribute value such as id="" is preserved. A #text-only object loses its JSON wrapper. For a root array ["a","b"], wrap with root root and item item produces <root><item>a</item><item>b</item></root>. Arrays must be nonempty and cannot be directly nested; heterogeneous items are checked individually and unsupported items fail the whole conversion.

    XML → JSON: strings and the real root remain

    Paste XML or load one .xml file, choose XML → JSON, select 2 or 4 spaces and convert. The real root is always retained as a JSON property. Text and attributes stay strings: 00123, true and apparent dates are not inferred as numbers, booleans or dates. Attributes appear first under @attributes; an attributed leaf always includes #text, including "". A leaf without attributes becomes a string. Same-name consecutive siblings form arrays; interleaved groups such as a/b/a are rejected because grouping would reorder them.

    Numbers and booleans become XML text and return as strings, with type-loss notices. Numeric spelling such as 9007199254740993, 1.2300 and -0 is preserved; a core precision warning is distinct from losing the JSON type. Non-finite overflow fails. Null and an empty object become the same empty element and return as ""; a one-item array cannot recover its array intent. A root array returns an object of repeated item children, not an inferred root array. Review all notice counts and first locations. There is no universal round trip or automatic repair.

    A constrained XML 1.0 data model

    Names contain 1–64 ASCII characters, start with a letter or underscore, then use letters, digits, underscore, hyphen or dot. Names beginning with xml in any case, namespace syntax and unsafe prototype-related names are rejected without aliases or renaming. Arbitrary JSON keys are not XML names. Strict JSON rejects duplicates, comments and extensions. XML must have one complete root, matching case-sensitive closing tags and distinct attributes.

    Namespaces, DTD/DOCTYPE, ENTITY declarations, processing instructions (PI), mixed text and child elements, interleaved siblings, unknown entities and malformed XML are rejected before external parsing. This tool does not support general XML, HTML, XSD, XPath, XInclude or XSLT. Only the five predefined entities and valid numeric character references are decoded once; &amp;lt; becomes the text &lt;, not <. CDATA text joins leaf text, and comments/CDATA delimiters/the XML declaration are omitted with notices.

    XML CRLF and CR normalize to LF. Literal attribute TAB/LF/CR normalize to spaces; numeric references preserve TAB/LF/CR values. Presentation whitespace between children is omitted with notices, while leaf spaces remain data. An XML empty leaf, not an empty document, becomes an empty JSON string. Semantic values and textual XML spelling are different: declarations, quotes, comments and layout are not reconstructed.

    UTF-8, limits and complete local exports

    Files must be strict UTF-8; extension and MIME are selection hints, not proof of valid content. One initial UTF-8 BOM is removed with a notice; a second initial BOM is rejected. Original editor/File CRLF/CR remain in the retained source and diagnostic coordinates. XML output has no BOM/declaration and ends with LF; JSON output follows its chosen indentation without a forced final LF. Downloads are converted.xml (application/xml) or converted.json (application/json), with UTF-8 charset.

    Input: 1,000,000 UTF-16 units and 2,000,000 UTF-8 bytes; one file up to 2,000,000 bytes. Output: 2,000,000 units and 4,000,000 bytes. JSON input permits 50,000 nodes and 100 container levels; XML permits 50,000 elements, 50,000 attributes, 100 attributes per element, 200,000 tokens and depth 40. Decoded data is bounded at 1,000,000 units; result JSON at 100,000 nodes/depth 100. Own conversion work is bounded at 8,000,000 units, core parsing/serialization at 1,000,000 each; diagnostic details 20, notice families 13, location text 4,096 and diagnostic metadata 16,384 units. These budgets apply together and do not measure every external CPU instruction. The Worker deadline is 8,000 ms.

    The read-only preview shows at most 50,000 UTF-16 units without splitting a surrogate pair. Copy/download always use the complete current output; a clipboard failure offers an explicit full manual-copy action. A local cancelable Worker processes the document without upload, browser-storage persistence or placing document text in URLs. Edit, mode/options, example, clear or file load invalidate old output and exports. Errors, limits, cancel and timeout never publish partial results. Without JavaScript or a local Worker, conversion is unavailable.
