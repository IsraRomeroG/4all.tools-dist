JSON Schema Generator

Enable JavaScript to infer a schema locally in your browser.

Each editor is one complete JSON document. A root array stays an array. Examples guide the schema; they do not prove the rules of your domain.

Processing stays in your browser. Samples are not uploaded or saved.

        Analyze documents before generating

        Paste a complete JSON document into each editor or open a local UTF-8 .json file. Add up to twenty independent samples. Choose Analyze samples, review the inferred fields, then select Generate schema. These actions are explicit; loading an example does not generate a result. Every sample must be valid strict JSON. Empty editors, duplicate decoded keys, comments, JSONC/JSON5 and numbers that lose precision stop the complete operation. No failing sample is discarded.

        An editor containing an array represents one array document. All elements contribute, including the last elements; the tool does not unwrap the array into separate samples. Multiple editors produce one common schema for their roots. Strings, numbers, booleans and null can also be roots.

        The array example is:

        [{"id":1},{"id":2,"nombre":"Ana"}]

        With inferred required fields, the complete array passes this schema:

        {
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "array",
  "items": {
    "type": "object",
    "properties": {
      "id": {
        "type": "integer"
      },
      "nombre": {
        "type": "string"
      }
    },
    "required": [
      "id"
    ],
    "additionalProperties": true
  }
}

        Presence, null and manual required fields

        id occurs in 2/2 objects and is required by default; nombre occurs in 1/2 and is optional. Marking nombre required produces a first mismatch at instance /0, keyword required, schema /items/required, missing property nombre. The schema remains exportable with the visible warning that it does not accept all samples. The report checks every complete document and gives one first mismatch per incompatible sample. Reset inferred required fields removes all manual overrides, including choices on other pages.

        For [ {"x":null}, {"x":"a"}, {} ], x is present in 2/3 objects with types null/string and is optional. Without the empty object, x is required and still nullable. Absence affects presence; null affects type. At a nested object, presence uses only objects observed at that location. A single observation shows presence but does not prove a domain requirement.

        [] produces type: "array" with items: {}: no element type was observed, so items are unrestricted. {} reveals no properties. Integer and fractional observations combine as number; other mixed types use a type union. Object and array branches are combined inline without inferring relationships or discriminators. The schema may therefore accept combinations absent from the examples.

        Fixed draft and conservative suggestions

        The fixed URI is http://json-schema.org/draft-07/schema#. The emitted vocabulary is $schema, type, properties, required, items, additionalProperties and optional root title/description. Objects stay open with additionalProperties: true. There is no draft selector, format rule, enum, range, pattern, reference, tuple or anyOf/oneOf/allOf inference.

        Enable format suggestions before analyzing to see conservative candidates for ASCII email, absolute HTTP(S) URI and valid Gregorian YYYY-MM-DD dates. At least two string observations must all match the same detector; one counterexample or a string longer than 1,024 UTF-16 units suppresses the candidate. Identical examples count as observations without proving independent domain evidence. Suggestions are visible metadata; format is not emitted or checked by the current validator. Copy the schema and paste it into the related validator manually; links transfer no data.

        Limits, complete exports and privacy

        Original input limits are 250,000 UTF-16 units per sample, 500,000 in total, and 1,000,000 bytes per file. Each sample allows depth 20 and 25,000 source nodes; all samples together allow 50,000. The model allows 2,000 inferred nodes and 2,000 properties, with logical depth 20. Parsing has 1,000,000 work units per document; precision has 1,000,000 shared units; inference and validation each have 5,000,000 shared units. Maxima cannot necessarily be reached simultaneously.

        The complete schema is limited to 100,000 UTF-16 units, 5,000 JSON nodes and JSON parse depth 60. Normalization retains semantic depth 40, 5,000 visits and 5,000 schema names. Root title allows 256 units and description 2,000; indentation is two or four spaces. Paths allow 2,048 units; at most twenty diagnostics and 8,192 diagnostic text units are published. Pages contain up to twenty-five entries and 20,000 text units, with 8,192 per entry. An oversized entry fails the complete analysis. Analysis and generation time out after 8 seconds; pages after 2 seconds. Limits, cancellation or operational errors publish no partial schema or partial checks.

        Files use strict UTF-8. One initial BOM is removed with a notice and coordinates remain relative to the visible original; a second initial BOM is invalid. Editing samples, starting a file load, reanalyzing or changing suggestions invalidates the snapshot and required choices. Changing required fields or schema options invalidates the output. Canceling terminates the Worker; analyze again to continue.

        Copy and download export the same complete current schema, regardless of the field page. Download uses schema.json, application/schema+json, UTF-8 without BOM, LF and no final newline. Clipboard failure offers manual copying from the full read-only output. Samples are processed locally without uploads, remote URLs, telemetry or content storage. JavaScript and a Worker-capable browser are required.
