JSON y JSONC: comentarios, comas finales y conversión

Distingue JSON de JSONC, convierte una configuración comentada a JSON estricto y comprueba qué se elimina y qué valores se conservan.

JSON estricto no admite comentarios ni comas finales. JSONC permite comentarios; aceptar comas finales depende del programa que lo lee. El modo JSONC a JSON de 4all.tools acepta ambas extensiones, las retira y valida la salida. Comprueba qué formato exige el destino: si necesita JSON, convierte el documento y conserva el original comentado.

Una configuración aceptada por tu editor puede fallar al enviarla a una API que exige JSON estricto. Cambiar la extensión de .jsonc a .json no transforma el contenido: los comentarios y las comas siguen ahí.

Qué diferencia a JSON, JSONC y JSON5

Sintaxis JSON estricto JSONC JSON5
Comentarios // y /* ... */ No Sí Sí
Coma tras el último campo o elemento No Depende del consumidor Sí
Cadenas con comillas simples No No Sí
Claves sin comillas No No Sí, si son identificadores admitidos

La gramática de RFC 8259 define JSON estricto. El borrador de especificación JSONC deja las comas finales como soporte opcional. En esta herramienta, el modo JSONC las acepta tanto en objetos como en arrays. Eso no garantiza que otro consumidor de JSONC las acepte.

Convierte una configuración comentada, paso a paso

Guarda una copia del original. Esta entrada es válida para el modo JSONC de 4all.tools:

{
  // URL usada en el entorno de pruebas
  "endpoint": "https://api.example.test/v1",
  "nota": "El texto /* demo */ debe conservarse",
  "reintentos": 3,
  "regiones": ["mx", "es",],
}
  1. Abre JSON Repair y pega la muestra en Texto de entrada.
  2. Elige JSONC a JSON.
  3. Selecciona Convertir para ejecutar la operación. Pegar o cambiar de modo no inicia la conversión.
  4. Revisa la salida propuesta, los cambios y las advertencias. Comprueba los valores con el original.
  5. Si el resultado es válido y coincide con los datos que necesitas, selecciona Copiar salida y utiliza esa versión en el destino.

Resultado esperado, formateado para facilitar la lectura:

{
  "endpoint": "https://api.example.test/v1",
  "nota": "El texto /* demo */ debe conservarse",
  "reintentos": 3,
  "regiones": ["mx", "es"]
}

El motor actual produce estos datos y valida el candidato como JSON estricto. La disposición anterior es editorial: la conversión real sustituye comentarios y comas finales por espacios y conserva los saltos de línea. Puede quedar una línea en blanco donde estaba el comentario y espacios antes de los cierres.

Qué se elimina y qué se conserva

En la muestra se retiran tres fragmentos:

  • El comentario de línea que empieza por // URL.
  • La coma después de "es", antes de ].
  • La coma después del array, antes de }.

El // de https://api.example.test/v1 y el texto /* demo */ dentro de la cadena son datos y se conservan. También se mantienen el número 3, su tipo numérico y el orden del array: primero "mx", después "es". No uses una sustitución global con expresiones regulares para borrar comentarios: puede eliminar partes de una URL o texto literal.

La pérdida de comentarios es deliberada. Si contienen instrucciones para mantener la configuración, guarda el original JSONC y genera una copia JSON para el consumidor que la exige.

Si la conversión sigue fallando

Revisa el diagnóstico antes de cambiar de modo. Una coma ausente, una cadena sin cerrar o un comentario de bloque incompleto siguen siendo errores. Si faltan separadores o cierres, consulta cómo localizar y corregir errores de sintaxis JSON y vuelve a convertir después de aplicar el cambio necesario.

Esta entrada queda fuera del modo JSONC:

{ entorno: 'pruebas' }

Tiene una clave sin comillas y una cadena con comillas simples. Su equivalente JSON estricto es:

{"entorno":"pruebas"}

Estas construcciones existen en JSON5; quitar comentarios no las convierte. Reparar JSON puede intentar corregir algunos casos mediante heurísticas, pero no es un convertidor completo de JSON5. Actívalo solo si necesitas esa reparación y puedes revisar cada inferencia: obtener sintaxis válida no demuestra que se haya recuperado el dato previsto.

Si trabajas con una respuesta de IA, consulta cómo revisar JSON generado por IA antes de usarlo, con ejemplos de envoltorios y valores truncados.

La herramienta también aplica límites de tamaño y complejidad y rechaza claves duplicadas. Son políticas del producto, no una definición universal de JSONC. Si aparece un aviso de límite, reduce la entrada; si hay claves duplicadas, decide cuál corresponde conservar. La página de JSON Repair detalla los límites actuales.
