¿Qué es JSON? Guía práctica de su sintaxis

Aprende qué es JSON, cómo funciona su sintaxis y por qué se utiliza para intercambiar datos estructurados.

Publicado: 25 de septiembre de 2026
Categorías: Guías de JSON

JSON es un formato de texto que permite representar datos con una estructura que distintos programas pueden leer. Sus siglas significan JavaScript Object Notation. Aunque su nombre procede de JavaScript, puede utilizarse con otros lenguajes: lo compartido son las reglas para escribir la información. Sirve, por ejemplo, para intercambiar datos entre aplicaciones, guardar ajustes o generar una exportación. Para entenderlo no necesitas programar; basta empezar por un dato conocido y observar cómo se escribe. Así lo define ECMA-404.

Un ejemplo de JSON, explicado paso a paso

Esta ficha describe un producto ficticio. Es JSON válido y puedes copiarlo como texto:

{
  "producto": "Cuaderno",
  "precio": 49.9,
  "disponible": true
}

La información dice que el producto se llama Cuaderno, que su precio es 49.9 y que está disponible. El ejemplo no asigna una moneda concreta.

Piensa en una ficha con etiquetas y datos. La etiqueta "producto" es una clave: identifica un dato. "Cuaderno" es su valor: la información asociada. Cada pareja también se puede llamar campo de la ficha.

La puntuación organiza esas parejas:

Signo Qué hace en el ejemplo
{ } Delimita un objeto, que agrupa datos mediante nombres.
: Relaciona una clave con su valor.
, Separa un campo del siguiente.
" " Delimita texto, tanto en las claves como en los valores de texto.

Observa que 49.9 y true no llevan comillas: son un número y un valor verdadero/falso, respectivamente. Más adelante veremos por qué eso importa.

Los nombres de las claves los elige quien diseña los datos. En una aplicación real debes respetar los nombres que espera: cambiar "precio" por "importe" no hace que el programa reconozca automáticamente ambos.

Para qué sirve JSON en la práctica

Imagina una tienda con una aplicación de inventario y una página de productos. El inventario prepara los datos del cuaderno como texto JSON; la página recibe ese texto, lo interpreta y muestra su nombre, precio y disponibilidad.

Una API es una interfaz mediante la que los programas se comunican. Puede permitir que la página solicite un producto y reciba una respuesta JSON. Los programas deben acordar qué significa cada campo: el formato organiza la información, mientras la aplicación decide cómo utilizarla.

Otros dos usos ayudan a ver la diferencia:

  • Configuración: una persona o un programa guarda ajustes, como un idioma o una preferencia de visualización. La aplicación los lee cuando necesita aplicar esa configuración.
  • Exportación: un programa escribe un archivo con datos para conservarlos o trasladarlos. Otro programa puede importarlo si entiende la estructura y el significado de sus campos.

JSON no envía ni guarda información por sí solo. El software realiza esas operaciones. Tampoco todas las APIs utilizan este formato: la representación se elige según lo que admitan los sistemas que participan.

Cómo se organiza JSON: objetos, listas y tipos

Podemos ampliar la misma ficha sin cambiar sus tres primeros datos:

{
  "producto": "Cuaderno",
  "precio": 49.9,
  "disponible": true,
  "colores": ["azul", "negro"],
  "vendedor": {
    "nombre": "Ana",
    "ciudad": "Puebla"
  },
  "observaciones": null
}

"colores" contiene un array, es decir, una lista ordenada. Los corchetes [ ] delimitan la lista y las comas separan sus elementos.

"vendedor" contiene otro objeto. Sus llaves agrupan el nombre y la ciudad de la persona que vende el producto. A esta organización de una estructura dentro de otra se le llama anidación.

JSON dispone de seis tipos de valores. Todos aparecen en la ficha ampliada. JSON.org describe estas estructuras y tipos.

Tipo Ejemplo Cómo leerlo
Texto o string "Cuaderno" Una cadena de texto entre comillas dobles.
Número 49.9 Un valor numérico, sin comillas.
Booleano true Verdadero; false significa falso.
Array ["azul", "negro"] Una lista de dos elementos.
Objeto {"nombre":"Ana","ciudad":"Puebla"} Datos agrupados mediante claves.
Nulo null Un valor nulo explícito.

En este catálogo, acordamos que "observaciones": null indica que no hay observación registrada. Esa interpretación pertenece al ejemplo: null no significa universalmente cero, texto vacío o propiedad ausente.

Las comillas pueden cambiar el tipo

Las seis muestras de esta tabla son documentos JSON válidos, pero cada pareja representa tipos diferentes:

Campo Valor con su tipo original Valor escrito como texto
Precio {"precio":49.9} {"precio":"49.9"}
Disponibilidad {"disponible":true} {"disponible":"true"}
Observaciones {"observaciones":null} {"observaciones":"null"}

Un programa puede necesitar sumar un precio numérico o consultar un booleano. Que dos valores se vean parecidos no los hace intercambiables. Las claves tampoco determinan el tipo: lo determina el valor escrito.

Aunque nuestros ejemplos usan objetos, un documento JSON completo también puede ser una lista, como ["azul","negro"], o un valor simple, como 49.9. No es obligatorio que empiece con una llave. RFC 8259, gramática y valores.

JSON, archivos y JavaScript: qué diferencia hay

Es útil distinguir el formato de los lugares y las formas en que una aplicación maneja la información:

Concepto Qué representa
Texto JSON La información escrita según las reglas que acabamos de ver.
Archivo .json Un archivo que contiene ese texto.
Datos de un programa Los valores que obtiene el programa al interpretar el texto y que puede consultar o modificar.

El mismo producto puede pasar por las tres formas: llega como texto, un programa interpreta sus campos y después guarda una nueva representación en un archivo.

JSON no es lo mismo que JavaScript. JavaScript es un lenguaje de programación; JSON es un formato de datos. Un objeto creado dentro de un programa JavaScript puede parecerse al texto JSON, pero no son lo mismo y sus reglas no coinciden en todo. MDN explica la relación entre ambos.

Interpretar ese texto se suele llamar parsear. Convertir datos a una representación textual se llama serializar. Generar texto no equivale a guardarlo: en JavaScript, JSON.stringify() hace esa conversión, pero no escribe un archivo por sí sola.

Del mismo modo, cambiar la extensión de cualquier archivo a .json no convierte su contenido en JSON válido.

Reglas de JSON y cinco errores comunes

La sintaxis es el conjunto de reglas para escribir el formato. En JSON estándar, las claves y los textos llevan comillas dobles; las comas separan miembros o elementos y no se colocan después del último.

Las siguientes entradas son deliberadamente incorrectas. La columna central muestra una corrección válida:

Entrada incorrecta Corrección válida Qué había que cambiar
{producto:"Cuaderno"} {"producto":"Cuaderno"} Poner comillas dobles alrededor de la clave.
{'producto':'Cuaderno'} {"producto":"Cuaderno"} Usar comillas dobles en lugar de simples.
{"precio":49.9,} {"precio":49.9} Eliminar la coma final.
{"producto":"Cuaderno" "precio":49.9} {"producto":"Cuaderno","precio":49.9} Añadir la coma entre los dos campos.
{"disponible":True} {"disponible":true} Escribir el literal true en minúsculas.

Además, false y null también se escriben en minúsculas. Los números decimales utilizan punto: 49.9. Esa regla no cambia porque en un país se use coma al escribir un precio en prosa.

JSON estándar no admite comentarios ni valores de JavaScript como undefined. Algunas herramientas aceptan variantes con otras reglas; para esta práctica, trabaja en modo JSON estándar. Referencia de sintaxis en MDN.

Los saltos de línea y la sangría facilitan la lectura, pero no corrigen una coma ausente. Si un editor marca un problema cerca de un campo, revisa también el separador anterior. El mensaje y la posición del error pueden variar según el programa.

Si ya tienes un documento rechazado, sigue la guía para encontrar y corregir errores de sintaxis JSON, con un ejemplo completo y correcciones mínimas.

Cómo abrir, guardar y comprobar un archivo JSON

Abrir uno existente o crear tu ejemplo

Un archivo JSON se puede leer con un editor de texto o de código. No necesitas ejecutar el contenido del archivo ni escribir código para leerlo.

  1. Abre el archivo desde el editor. Para crear uno, abre un documento de texto nuevo y copia el primer ejemplo del cuaderno.
  2. Lee o modifica sus campos. Si aparece en una sola línea, el formateo puede hacerlo más legible.
  3. Comprueba la sintaxis después de editar.
  4. Guarda como texto UTF-8 con el nombre producto.json. Comprueba que no haya quedado como producto.json.txt.

Usa texto plano, sin formato de procesador de textos. Un editor de código puede añadir resaltado y avisos. Por ejemplo, VS Code permite editar y validar JSON; selecciona el modo JSON estándar para esta práctica.

Formatear y validar comprueban cosas diferentes

Operación Qué hace
Formatear Organiza la presentación para facilitar la lectura.
Validar sintaxis Comprueba si el texto sigue las reglas de JSON.
Validar contra un esquema Comprueba restricciones declaradas, como exigir un precio numérico.

Un esquema describe los requisitos que deben cumplir los datos. Puede indicar campos obligatorios y tipos permitidos. Validar sintaxis no comprueba automáticamente ese esquema, ni ninguna de las dos comprobaciones demuestra que los datos sean ciertos. Introducción a JSON Schema.

Una práctica de cuatro pasos

Usa el primer ejemplo en un editor que compruebe JSON o en un validador de sintaxis:

  1. Comprueba el original: debe ser válido.
  2. Añade una coma después de true, antes de la llave final: pasa a ser inválido.
  3. Elimina esa coma: vuelve a ser válido.
  4. Escribe el precio entre comillas: sigue siendo válido, pero ahora el precio es texto.

Tras el cuarto paso tendrás:

{
  "producto": "Cuaderno",
  "precio": "49.9",
  "disponible": true
}

Supongamos que el catálogo exige un precio numérico. Esta muestra incumple ese requisito aunque el validador sintáctico la acepte. Para terminar, quita las comillas del precio, vuelve a comprobar y guarda.

Reparar una entrada significa modificarla. No es lo mismo que formatearla: antes de aceptar una corrección, comprueba que conserva la información que pretendías representar.

Opcional: leer y generar JSON con JavaScript

Si estás aprendiendo JavaScript, este ejemplo conecta el texto con los datos del programa. El bloque siguiente es JavaScript, no un documento JSON:

const textoJson = '{"producto":"Cuaderno","precio":49.9,"disponible":true}';
const datos = JSON.parse(textoJson);

console.log(datos.producto); // Cuaderno
datos.precio = 59.9;

const textoActualizado = JSON.stringify(datos, null, 2);
console.log(textoActualizado);

La primera salida es Cuaderno. Después se muestra este texto JSON:

{
  "producto": "Cuaderno",
  "precio": 59.9,
  "disponible": true
}

JSON.parse() interpreta la cadena y aquí produce un objeto. El programa cambia su precio; JSON.stringify(datos, null, 2) genera texto con sangría de dos espacios.

Las comillas simples externas delimitan la cadena de JavaScript: no pertenecen al JSON que contiene. Los comentarios también son válidos en este bloque porque es JavaScript.

Parsear puede devolver otros valores, no sólo objetos. Serializar tiene limitaciones para ciertos valores y estructuras del lenguaje. Y este código únicamente produce texto: para conservarlo en un archivo hace falta otra operación. Puedes ampliar en JSON.parse() y JSON.stringify().

Opcional: JSON frente a CSV y XML

El formato adecuado depende de la información y de los programas que deban leerla:

Formato Organización habitual Un caso donde encaja
JSON Objetos y listas que pueden anidarse. Compartir productos con colores y datos de vendedor.
CSV Filas y campos, como una tabla sencilla. Llevar una lista de productos y precios a una hoja de cálculo.
XML Elementos delimitados por etiquetas. Intercambiar información o documentos con una estructura de marcado acordada.

Esta tabla ofrece una orientación inicial; la elección depende de los datos y de los programas que los utilizarán. Consulta las reglas de CSV en RFC 4180 y de XML en W3C si necesitas profundizar.
