Errores de sintaxis JSON: cómo encontrarlos y corregirlos

Localiza una coma, comilla o llave incorrecta, aplica la corrección mínima y comprueba que tu JSON vuelve a ser válido.

Para corregir un error de sintaxis JSON, valida el texto, revisa la posición indicada y el carácter anterior, haz una corrección mínima y vuelve a validar. El lugar señalado puede ser donde el analizador dejó de entender el documento: la causa puede estar en la línea anterior.

  1. Pega el documento completo en el validador JSON y selecciona Validar JSON.
  2. Si el diagnóstico incluye línea y columna, revisa esa zona y el final de la línea anterior.
  3. Corrige un problema por vez: una coma ausente, una coma sobrante, una comilla o un cierre.
  4. Vuelve a validar el documento completo después de cada cambio.

Conserva una copia del original para poder revisar qué modificaste. El validador señala problemas; tú decides la corrección.

Cómo leer la ubicación del error

Una coma faltante puede pasar inadvertida hasta que aparece la siguiente clave. Un cierre ausente puede detectarse al llegar al final del texto. Por eso conviene leer alrededor de la posición marcada, en lugar de borrar directamente el carácter señalado.

El mensaje y la ubicación dependen del programa que analiza el JSON. MDN recoge ejemplos de diagnósticos de análisis; no todos los analizadores usan los mismos textos.

Si no aparece una ubicación, recorre el documento desde el principio y revisa dónde acaba cada valor y comienza el siguiente. En un archivo grande, vuelve primero a la zona que acabas de editar. Añadir sangría manualmente puede ayudarte a seguir la estructura; la sangría por sí sola no corrige el error.

Ejemplo: el error aparece en una clave, pero falta una coma antes

Este documento es inválido:

{
  "pedido": {
    "id": "A-17"
    "total": 42
  }
}

El analizador puede señalar "total" o una posición cercana. La clave está bien escrita: falta la coma que separa el campo anterior del siguiente. Añádela después de "A-17":

{
  "pedido": {
    "id": "A-17",
    "total": 42
  }
}

Pega esta segunda versión y vuelve a seleccionar Validar JSON. El resultado esperado es JSON válido. No hemos cambiado el identificador ni el total; hemos añadido el separador que faltaba.

Cuatro fallos que puedes corregir con un cambio pequeño

Las entradas de la segunda columna son deliberadamente inválidas. Las de la última columna son documentos JSON válidos:

Problema Entrada inválida Cambio mínimo Corrección válida
Falta una coma entre campos {"id":"A-17" "total":42} Añadir la coma después del identificador. {"id":"A-17","total":42}
Sobra una coma al final del array {"etiquetas":["uno","dos",]} Quitar la coma posterior a "dos". {"etiquetas":["uno","dos"]}
La clave lleva comillas simples {'activo':true} Sustituir las comillas de la clave por comillas dobles. {"activo":true}
Falta cerrar el objeto {"activo":true Añadir } al final. {"activo":true}

Las comas separan campos de objetos o elementos de arrays; las claves y los valores de texto se delimitan con comillas dobles. Estas reglas forman parte de la sintaxis JSON definida en ECMA-404.

Si el documento contiene comentarios

JSON estricto no admite comentarios. Si el original es una configuración JSONC, consulta la diferencia entre JSON y JSONC y cómo convertirla. Esa conversión retira comentarios y comas finales; conserva el original si sus anotaciones son necesarias para mantener la configuración.

Si el problema está dentro de una cadena

En {"nota":"Dijo "hola""}, las comillas de "hola" cierran la cadena antes de tiempo. Para conservar esas comillas como parte del texto, escápalas:

{"nota":"Dijo \"hola\""}

Evita sustituir todas las comillas automáticamente: podrías modificar caracteres que sí pertenecen al valor.

Si el documento termina antes de lo esperado

En el último caso de la tabla, solo falta una llave. Si la entrada se corta a mitad de un texto o de un registro, revisa primero si copiaste o recibiste el documento entero. Añadir cierres puede producir sintaxis válida sin recuperar los datos que faltan.

Comprueba la corrección y conserva el significado

Vuelve a validar todo el documento, aunque solo hayas cambiado una línea. Si aparece otro error, repite el procedimiento. Una vez que valide, elige si necesitas formatearlo o minificarlo y revisa los valores antes de guardarlo.

Comprueba también lo que la aplicación espera. {"total":"42"} y {"total":42} son JSON válidos, pero el primero contiene texto y el segundo un número. La validación de sintaxis no aplica un JSON Schema ni verifica requisitos de negocio.

Si la herramienta comunica un límite de tamaño, una cancelación o un fallo de lectura, atiende ese aviso antes de cambiar la puntuación: no demuestra un error de sintaxis. Cuando falte contexto sobre objetos, arrays o tipos, consulta la guía de qué es JSON.
