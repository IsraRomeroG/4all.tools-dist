JSON generado por IA: cómo repararlo y revisar el resultado

Conserva la respuesta original, revisa los cambios propuestos y decide si puedes usar el JSON o necesitas solicitar los datos completos.

Antes de corregir el JSON que te devolvió una IA, guarda la respuesta original. Si el documento está dentro de un bloque Markdown, copia su contenido y valídalo. Puede que no necesite reparación. Si la necesita, compara el resultado con el original antes de usarlo: reparar la sintaxis no recupera los datos que faltan. Para eso tendrás que consultar la fuente o pedir una respuesta completa.

Qué hacer con la respuesta que recibiste

  1. Guarda una copia de la respuesta completa para poder comparar los cambios.
  2. Si hay un único bloque Markdown completo, copia solo el documento interior. Si hay prosa mezclada o varios bloques, identifica primero cuál corresponde a la tarea.
  3. Valida el documento. Si ya tiene sintaxis correcta, pasa a comprobar sus datos; reparar no es un paso obligatorio.
  4. Si necesita reparación, abre el reparador JSON, pega el original en Texto de entrada, elige Reparar JSON y selecciona Reparar. Pegar o cambiar de modo no ejecuta la operación.
  5. Revisa la salida propuesta, la advertencia y los cambios. Compara los valores y campos con el original completo o la fuente.
  6. Cuando hayas comprobado los cambios y los datos que necesita tu aplicación, selecciona Copiar salida.
Lo que recibiste Acción inicial Qué comprobar
Un bloque Markdown completo con JSON válido dentro Copiar solo el JSON y validarlo. Que se haya retirado únicamente el envoltorio.
JSON con comentarios o comas finales Usar JSONC a JSON; consulta la guía de JSON y JSONC. Que se retiren esas extensiones y se conserven los valores.
Otros errores, como comillas simples o claves sin comillas Corregir el error a mano si sabes cómo, o intentar Reparar JSON. Qué cambió el reparador y si añadió algún valor.
Un documento cortado a mitad de un valor o registro Pedir el documento completo o consultar la fuente. Qué contenido falta; añadir cierres no lo recupera.

Si reconoces el error y quieres corregirlo a mano, consulta cómo corregir errores de sintaxis JSON. Cuando la respuesta mezcle explicaciones y varios bloques de código, identifica primero el JSON que necesitas: el reparador no puede decidir por ti cuál usar.

Un bloque Markdown completo: retirar el envoltorio

Esta es la respuesta de ejemplo, incluidas las marcas Markdown:

```json
{"pedido":"A-17","unidades":2,"entregado":false}
```

Datos esperados al retirar únicamente el envoltorio:

{"pedido":"A-17","unidades":2,"entregado":false}

El JSON del bloque ya es válido; basta con copiarlo y validarlo. Al probar la respuesta completa en Reparar JSON, el reparador quitó las marcas Markdown y dejó los saltos de línea alrededor del documento. Los datos quedaron como se muestra arriba.

Comprueba que pedido conserve el texto "A-17", unidades el número 2 y entregado el booleano false. En este ejemplo solo deben desaparecer las marcas Markdown. El reporte puede agrupar varios cambios, así que compara también el contenido, no solo la cantidad de entradas del reporte.

Al elegir ese modo aparece la advertencia «La reparación es heurística y puede cambiar el significado. Revisa los cambios.» En esta operación, el diagnóstico también indica: «La salida se obtuvo mediante una reparación heurística. Comprueba que conserva el significado correcto.» La advertencia del modo permanece incluso cuando una entrada válida pasa sin cambios.

Un documento truncado: un valor añadido no es un valor recuperado

Ahora la respuesta termina justo después de los dos puntos:

{"pedido":"A-17","unidades":

Resultado de probar este ejemplo en Reparar JSON:

{"pedido":"A-17","unidades":null}

El reparador añadió null y una llave de cierre. Ahora la sintaxis es válida, pero seguimos sin saber cuántas unidades había: podrían haber sido 2, 20 u otra cantidad. Ese null no es el valor recuperado. Tampoco sabemos si la aplicación acepta nulos en ese campo o si faltaban más datos del pedido.

Pide de nuevo la respuesta completa o busca la cantidad en la fuente original y escríbela en el campo. El resultado que ves aquí corresponde a este ejemplo: con otro corte, el reparador puede hacer cambios distintos o fallar. Lo mismo ocurre si falta parte de un texto o de un array; añadir el cierre no repone lo que se perdió.

¿Tu aplicación espera texto o un número?

Estos dos documentos tienen sintaxis válida:

{"unidades":"2"}
{"unidades":2}

El primero contiene texto y el segundo un número. RFC 8259 distingue estos tipos de valores. Si el contrato de tu aplicación exige un número, el primer documento no lo satisface. Revisa la fuente antes de corregirlo: convertir tipos a ciegas puede cambiar datos, como un identificador "002" cuyos ceros forman parte del valor.

El reparador no conoce las reglas de tu aplicación: qué campos son obligatorios, qué tipos admite cada uno o cuántos registros pediste. Tendrás que comprobarlo aunque el JSON pase la validación a la primera.

Revisión antes de usar la salida

  • ¿Solo se quitaron envoltorios o se añadieron valores, comillas o cierres?
  • ¿Siguen presentes los campos obligatorios y la cantidad de registros esperada?
  • ¿Se conservaron identificadores, números, booleanos y nulos, con los tipos exigidos por el destino?
  • ¿Hay advertencias, por ejemplo sobre posible pérdida de precisión en números grandes o muy precisos? Comprueba su texto original y la representación que utilizará tu aplicación.
  • ¿Puedes justificar cada cambio con el documento completo o la fuente?

Si la herramienta indica éxito, la salida tiene sintaxis válida; aún debes comprobar los datos que haya añadido. Si se detiene por un límite de procesamiento, lee el mensaje para saber qué límite se alcanzó. Ese fallo no permite concluir que el JSON esté mal escrito o no tenga arreglo.

Puedes usar el resultado cuando los cambios conserven los datos y estos cumplan lo que necesita tu aplicación. Si encuentras un valor o un tipo incorrecto, corrígelo con ayuda de la fuente. Cuando falte información y no tengas dónde comprobarla, pide los datos otra vez.

En tu próxima petición, especifica que quieres solo JSON e indica los campos, sus tipos y cuántos registros esperas. Así será más fácil detectar qué falta o qué no encaja cuando revises la respuesta.
