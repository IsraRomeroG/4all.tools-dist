Genera tipos Go a partir de ejemplos JSON completos

Infiere structs y mapas raw de Go localmente, conserva los lexemas numéricos con json.Number y conoce las capacidades de los punteros opcionales.

Espacio de trabajo de la herramienta

JSON a Go

Declaraciones Go 1.22+; sólo encoding/json y biblioteca estándar.

Todos los números usan json.Number para conservar sus lexemas. Los punteros opcionales aceptan null aunque no aparezca en las muestras y colapsan ausencia/null a nil; omitempty puede omitir null explícito. Raw conserva el token null. Los structs no exigen campos requeridos ni rechazan null escalar. Las claves fuera del subconjunto de tags amplían el objeto completo a un mapa raw.

Activa JavaScript para generar código. Puedes leer y editar el JSON.

Este navegador no puede iniciar el Worker local. La generación no está disponible.

Todos los elementos y documentos aportan al mismo contrato. Un array raíz sigue siendo un array. La ausencia de un campo es distinta de null.

Hasta 20 documentos, 1.000.000 de unidades UTF-16 de entrada y 2.000.000 de salida; también se aplican otros presupuestos de recursos.

Tu JSON se procesa localmente en un Worker del navegador. No se envía ni se guarda.

Al cambiar a un documento se conserva sólo el ejemplo activo. Confirma o cancela.

Usa entre 1 y 64 letras y dígitos ASCII; comienza por una letra. Los nombres reservados se rechazan.

        Ejemplos completos y arrays raíz

        Pega JSON estricto o selecciona un archivo UTF-8 local. Genera desde un documento o hasta veinte ejemplos completos. Todos los elementos y campos tardíos contribuyen; un array raíz sigue siendo un array. Entradas vacías, claves decodificadas duplicadas, comentarios, comas finales y documentos concatenados detienen la generación y conservan tus ejemplos.

        El editor muestra el ejemplo activo y el total. Después de generar, revisa el nombre del archivo, la expresión del tipo raíz, los nodos JSON y el tamaño del código completo.         [{"id":1},{"id":2,"nombre":"Ana"}]
        package generated

import "encoding/json"

type RootItem struct {
  Id json.Number `json:"id"`
  Nombre *string `json:"nombre,omitempty"`
}

type Root []RootItem

        Tags exactos, mapas y presencia con punteros

        Las claves no vacías que cumplen [A-Za-z0-9_ .:/-]+ reciben campos exportados con tags json exactos. La clave literal - usa json:"-," o json:"-,omitempty". Las colisiones sólo cambian identificadores Go. Otra clave, incluidas comillas, coma, backslash, backtick, controles o Unicode, amplía el objeto completo a map[string]json.RawMessage nombrado; el mapa conserva todas las claves Unicode válidas. Sustitutos aislados en claves detienen la generación. Los objetos vacíos también se representan como mapas raw.

        La ausencia usa *T y omitempty, excepto en campos raw. T más null observado usa un solo puntero. False, cero y string vacío presentes mantienen punteros no nil. Los punteros opcionales aceptan null aunque no se haya observado: ausencia y null terminan en nil, por lo que una serialización posterior puede omitir null explícito. Raw distingue ausencia nil del token null recibido. Go no valida requeridas ni prohíbe null en escalares al deserializar. Los avisos explican estas capacidades; los tipos no son validación runtime ni garantía de round-trip global.

        Números y exportación local completa

        Cada número usa json.Number, incluidos 9007199254740993, 1.0, 1e3 y -0. String() conserva el lexema sin convertirlo a float64. El aviso de precisión del parser sigue visible y no significa pérdida de json.Number. Unknown, null exclusivamente y uniones de dos o más ramas no null usan json.RawMessage con avisos. Las raíces number/raw usan alias que conservan unmarshalling; objeto/null usa alias a puntero. Sólo se emiten declaraciones alcanzables e imports necesarios en package generated, sin deserializador propio.

        Límites: 20 muestras, 1.000.000 unidades UTF-16 de entrada, 4.000.000 bytes UTF-8 agregados y por archivo, profundidad 200, 100.000 nodos fuente/visitas de inferencia, 1.000.000 unidades de parseo, 10.000 tipos, 20.000 campos, 2.000.000 unidades de fusión, 2.000 declaraciones, 4.000.000 unidades de emisión y 15 segundos. Salida: 2.000.000 unidades UTF-16 y 8.000.000 bytes. Los máximos no se alcanzan necesariamente juntos; exceder un límite duro no produce código parcial.

        La vista previa contiene hasta 20.000 unidades UTF-16; copiar y descargar incluyen todo types.go vigente como text/plain;charset=utf-8, UTF-8 sin BOM y LF final. Se muestran hasta 100 diagnósticos y 50 filas de nombres con 10.000 unidades en total, indicando lo omitido. La copia denegada ofrece copia manual explícita del código completo. Se retira un BOM inicial sólo al parsear; las posiciones corresponden al editor original. Cancelar termina el Worker; editar, cambiar modo, orden u opciones invalida la salida. El procesamiento queda en un Worker local, offline tras cargar los assets, sin subidas, almacenamiento ni datos en enlaces relacionados. Se requieren JavaScript y Worker; el navegador no compila ni ejecuta el Go generado.
