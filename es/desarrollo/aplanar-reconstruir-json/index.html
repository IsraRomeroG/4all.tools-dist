Aplana y reconstruye rutas JSON en tu navegador

Convierte JSON estricto en rutas reversibles con puntos o corchetes y reconstruye mapas localmente, conservando vacíos y tokens numéricos y rechazando ambigüedades.

Espacio de trabajo de la herramienta

Aplanar y reconstruir JSON

Activa JavaScript para procesar JSON localmente en el navegador.

Operación

La raíz es $. Una propiedad simple se escribe $.name; una clave literal con punto usa $["a.b"]; un índice usa $[0]. El mapa plano vacío {} no es válido; {"$":{}} representa un objeto vacío. Hay conflicto cuando una ruta es prefijo de otra, como {"$.a":1,"$.a.b":2}. Se rechazan arrays dispersos, por ejemplo {"$[2]":"x"}. No cualquier mapa con puntos se puede reconstruir sin ambigüedad. La operación inversa vuelve a comprobar los límites.

Usar un resultado cambia a la operación inversa. Se vuelven a comprobar sus límites y no se ejecuta automáticamente.

Archivo: 8.000.000 bytes; entrada: 2.000.000 unidades UTF-16; profundidad: 200; nodos: 100.000; entradas: 50.000; salida: 2.000.000 unidades UTF-16.

Límites de trabajo

Límites de trabajo: 1.000.000 unidades de análisis, 1.000.000 de transformación y 1.000.000 de serialización. Las rutas admiten 200 segmentos, 10.000 unidades cada una y 1.000.000 en total; los índices llegan a 99.999. No se garantizan todos los máximos a la vez.

El procesamiento permanece en este navegador. No hay cargas, URLs remotas, borradores guardados ni contenido del documento en URLs o registros.

    Aplana o reconstruye con una acción explícita

    Pega JSON estricto o abre un archivo .json UTF-8 local. Elige Aplanar JSON para crear un mapa de rutas o Reconstruir JSON para rehacer un documento desde un mapa; después ejecuta la operación. Cargar un ejemplo, abrir un archivo, editar el texto o cambiar opciones nunca inicia la transformación. Ambos modos comparten página y URL canónica.

    La entrada de ejemplo compartida es:

    {"user":{"name":"Ana"},"items":[1,{},[]],"a.b":null,"":true}

    Con rutas dot, el mapa minificado es:

    {"$.user.name":"Ana","$.items[0]":1,"$.items[1]":{},"$.items[2]":[],"$[\"a.b\"]":null,"$[\"\"]":true}

    Con rutas bracket, el mapa minificado es:

    {"$[\"user\"][\"name\"]":"Ana","$[\"items\"][0]":1,"$[\"items\"][1]":{},"$[\"items\"][2]":[],"$[\"a.b\"]":null,"$[\"\"]":true}

    Ambos mapas reconstruyen los datos de entrada. La salida predeterminada usa dos espacios; los ejemplos están minificados para comparar mejor las rutas.

    Rutas, raíces y valores vacíos

    El formato es un objeto JSON no vacío y sin envelope. Cada clave es una ruta absoluta desde $; cada valor es una primitiva, un objeto vacío {} o un array vacío []. Los contenedores no vacíos se infieren de los segmentos tipados. Una raíz primitiva o vacía usa una sola entrada $, como {“$”:null} o {“$”:{}}. Un objeto o array raíz no vacío se representa mediante sus hojas descendientes. Un mapa vacío {} no es válido porque no identifica el valor raíz.

    $ significa raíz, $.name significa la propiedad simple name, $[“a.b”] significa la propiedad literal a.b y $[0] significa el índice cero de un array. $[“0”] es una propiedad llamada 0; $[0] es un índice. La notación dot usa cadenas JSON entre corchetes para claves con puntos o delimitadores, por ejemplo a.b, x[y], comillas, barras inversas, Unicode o la cadena vacía. La notación bracket escribe cada propiedad como cadena JSON entre corchetes. La reconstrucción acepta dot, bracket y mezclas de ambos. Este es el formato de rutas de la herramienta, no JSONPath completo: no incluye comodines, filtros, slices ni separadores personalizados.

    Los objetos y arrays vacíos se conservan como valores hoja explícitos, por ejemplo {“$.settings”:{},“$.items”:[]}. Los arrays deben ser densos desde cero. Una ruta de propiedad y una de índice no pueden compartir el mismo contenedor. Se rechazan alias duplicados, una hoja con descendientes, valores de mapa que sean objetos o arrays no vacíos y arrays dispersos. Por ejemplo, {“$.a”:1,“$[0]”:2} exige tipos de contenedor incompatibles; {“$.a”:1,“$.a.b”:2} tiene conflicto entre hoja y descendiente, y {“$[2]”:“x”} dejaría índices ausentes. No se sobrescriben valores, no se rellenan huecos con null ni se aplica «gana el último».

    JSON estricto y valores

    La entrada debe ser JSON estricto: se rechazan comentarios, JSONC, JSON5 y sintaxis mal formada. Las claves duplicadas al decodificarse, como {“a”:1,“\u0061”:2}, fallan en vez de reemplazarse silenciosamente. Los enteros grandes, decimales, cero negativo y exponentes salen de sus tokens numéricos originales, incluidos 9007199254740993, 0.10000000000000001, -0 y 1E+02. Un aviso de precisión describe la aproximación interna del parser, no un redondeo de la salida. Los números fuera del rango del parser, como 1e400, fallan explícitamente.

    El recorrido de ida y vuelta dentro de los límites conserva los valores JSON, las claves, las posiciones de arrays y los tokens numéricos. No conserva espacios de origen, escritura exacta de escapes ni el orden original de miembros de objetos. La salida se reformatea con LF, sin BOM ni salto final.

    Límites y salida completa

    Los archivos locales admiten hasta 8.000.000 bytes y la entrada hasta 2.000.000 unidades UTF-16. La transformación admite profundidad 200, 100.000 nodos JSON, 50.000 entradas del mapa, rutas de hasta 200 segmentos y 10.000 unidades UTF-16 cada una, y salida de hasta 2.000.000 unidades UTF-16. Análisis, transformación y serialización tienen cada uno 1.000.000 unidades de trabajo. Los índices de array llegan hasta 99.999. La operación vence a los 15 segundos; recuperar la salida completa tarda como máximo 5 segundos. Se conservan hasta 100 diagnósticos y una vista previa de 20.000 unidades. No se garantizan todos los máximos a la vez.

    Una vista previa truncada puede ser JSON incompleto. Copiar JSON y Descargar JSON recuperan toda la salida vigente, incluido el contenido posterior al límite. Si falla el portapapeles, usa el campo de copia manual completa. Las descargas usan json-flattened.json o json-reconstructed.json, MIME JSON y UTF-8. Usar resultado como entrada recupera el snapshot completo, cambia al modo inverso y vuelve a comprobar sus límites. No ejecuta la operación automáticamente.

    El procesamiento permanece en este navegador. Los archivos, la copia y las descargas requieren una acción tuya; no hay cargas, URLs remotas, borradores guardados ni entrada o salida en URLs o registros. Cancelar conserva la entrada y las opciones. Editar, cambiar el modo u opciones, limpiar o cargar otro archivo invalida el resultado anterior.
