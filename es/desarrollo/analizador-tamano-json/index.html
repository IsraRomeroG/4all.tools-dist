    Métricas exactas

    Los bytes miden la codificación UTF-8 del texto actual del editor. La longitud usa unidades UTF-16, no caracteres visibles. KiB y MiB auxiliares usan base 1024. El ahorro elimina whitespace JSON fuera de strings y un BOM inicial; no mide compresión, tráfico de red ni RAM.

    La profundidad de ruta cuenta propiedades e índices desde raíz 0. La de contenedores cuenta objetos y arrays en una cadena: contenedor raíz 1, primitiva raíz 0. Las claves son miembros de objetos, no índices de arrays.

    Analizar el texto actual

    Pega un documento JSON estricto o abre un archivo .json UTF-8 y pulsa Analizar JSON. Las raíces primitivas, strings vacíos, null, {} y [] son válidos. Se rechazan claves duplicadas decodificadas, como {“a”:1,“\u0061”:2}. JSONC, JSON5 y reparación quedan fuera. Se requieren JavaScript y un Worker local. Todo se procesa en esta pestaña: no se suben ni se guardan entrada e informe en storage, logs o URLs. Las herramientas relacionadas abren sin transferir el documento.

    Bytes, longitud y minificación conservadora

    Los bytes originales codifican el texto actual del editor en UTF-8, incluidos espacios y BOM inicial. Se mide la fuente adoptada: el editor puede normalizar saltos de línea y no se promete igualdad con el tamaño del archivo. La longitud cuenta unidades UTF-16, no caracteres visibles. KiB y MiB usan base 1024.

    La minificación retira sólo SP, TAB, LF y CR fuera de strings y un BOM inicial permitido. Conserva orden de claves, espacios internos, escapes Unicode y números como 1.0, 1e0, -0 y 9007199254740993. No serializa el valor semántico JavaScript. El aviso de precisión describe una aproximación interna; bytes y conteos no redondean el número. Un overflow como 1e999 se rechaza. Un segundo BOM inicial es inválido.

    El texto {“é”:“😀”} mide 10 unidades UTF-16 y 13 bytes UTF-8. Los strings equivalentes “\u00E9” y “é” ocupan tamaños fuente distintos: los escapes se conservan. Un sustituto aislado escapado sigue como texto del escape; TextEncoder sustituye los aislados literales según sus reglas, mientras el parser estricto determina la sintaxis. No se normaliza Unicode.

    Nodos, profundidades y detalle acotado

    Cada valor cuenta una vez, incluida raíz y contenedores vacíos. Las claves cuentan miembros de objetos, no índices ni nodos string. Los porcentajes usan cantidad de nodos, no bytes; los ceros se muestran y el redondeo puede no sumar 100%.

    La profundidad de ruta cuenta propiedades e índices desde raíz 0. La de contenedores cuenta objetos y arrays en una cadena: contenedor raíz 1, primitiva raíz 0. Los arrays mayores se ordenan por elementos directos, no bytes del subárbol; las rutas profundas incluyen todos los nodos, no sólo hojas. Empates por preorden fuente, también claves numéricas en orden textual. Cada lista retiene hasta 20 filas e indica elegibles, mostradas y omitidas; las métricas globales siempre son completas. El array del ejemplo es $.a con 2 elementos; las rutas empiezan $.a[1].b, $.a[0], $.a[1].

Las rutas o trabajo pueden fallar dentro del tamaño/nodos admitidos; un fallo duro no ofrece informe parcial. Omitir detalle es una selección acotada exitosa.

    Los tamaños describen codificación UTF-8, no gzip/Brotli, tráfico HTTP, RAM JavaScript ni tokens de modelos. No hay bytes por subárbol, treemap, descarga minificada, exportación de informe ni transferencia del documento. Los archivos UTF-8 estrictos conservan BOM inicial para medir; se avisa su retiro y sus tres bytes cuentan en el ahorro.
