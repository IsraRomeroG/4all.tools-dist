Convierte JSON y XML localmente

Convierte JSON estricto y un subconjunto de datos XML 1.0 localmente, con raíces explícitas, atributos, elementos repetidos y avisos de pérdidas.

Espacio de trabajo de la herramienta

XML pierde tipos JSON e intención de arrays de un ítem. Sin round-trip universal: null y objeto vacío pueden ser el mismo elemento vacío. XML → JSON conserva strings y la raíz real.

Usa @attributes para atributos string y #text para texto de hojas. Arrays producen elementos repetidos. Nombres ASCII; sin namespaces ni contenido mixto. Leer explicación completa del modelo

    Modelo y subconjunto admitido

    Usar la única propiedad raíz requiere objeto JSON con una propiedad: su nombre será la raíz XML. Envolver con nombre raíz añade la raíz elegida al contenido. Un array raíz usa el nombre de ítem; arrays de propiedad repiten su nombre. Arrays no vacíos y sin anidamiento directo. @attributes es objeto de valores string; #text es string permitido solo sin hijos, incluso vacío o whitespace. Atributos XML vuelven en @attributes; una hoja con atributos incluye #text. Hijos contiguos del mismo nombre pasan a arrays; grupos intercalados se rechazan para conservar orden. Una hoja XML vacía sin atributos vuelve como string JSON vacío; con atributos conserva #text="" dentro de un objeto. Números y booleanos pierden tipo; null, objetos vacíos y arrays singleton pierden intención. Subconjunto de datos XML 1.0: nombres ASCII de 1–64 caracteres, sin prefijo xml, namespaces, DTD ni processing instructions. Solo entidades predefinidas y referencias numéricas se decodifican una vez. Comentarios, delimitadores CDATA, declaración y whitespace de presentación se omiten con avisos. Espacios de hojas conservados; se normalizan finales de línea XML y whitespace literal de atributos. Sin inferencia de tipos ni reparación automática.

    JSON → XML: elige la raíz explícitamente

    Pega JSON estricto o carga un archivo local .json, elige JSON → XML y pulsa Convertir. La opción predeterminada Usar la única propiedad raíz (document) requiere un objeto con una sola propiedad ordinaria. Envolver con nombre raíz (wrap) añade la raíz elegida, inicialmente root; nunca extrae automáticamente una raíz existente. Un array raíz usa el nombre de ítem, inicialmente item; este ajuste no renombra arrays bajo propiedades. Elige salida compacta o con formato y 2 o 4 espacios. La salida compacta conserva el ajuste de indentación sin añadir espacios de presentación.

    {"catalog":{"@attributes":{"id":"00123"},"item":[{"@attributes":{"code":"a"},"#text":"uno & dos"},{"@attributes":{"code":"b"},"#text":"tres"}]}}
    <catalog id="00123"><item code="a">uno &amp; dos</item><item code="b">tres</item></catalog>

    @attributes es un objeto con valores exclusivamente string. #text debe ser string en una hoja sin hijos, incluso vacío o solo espacios. Las propiedades ordinarias crean hijos en orden fuente; los arrays repiten el nombre de esa propiedad. Un objeto @attributes: {} vacío se omite con aviso; el valor vacío de un atributo, como id="", sí se conserva. Un objeto con solo #text pierde su envoltura JSON. El array raíz ["a","b"], con wrap raíz root e ítem item, produce <root><item>a</item><item>b</item></root>. Los arrays deben ser no vacíos y no pueden anidarse directamente; cada ítem heterogéneo se valida y cualquier ítem no representable hace fallar toda la operación.

    XML → JSON: strings y raíz real conservados

    Pega XML o carga un .xml, elige XML → JSON, selecciona 2 o 4 espacios y convierte. La raíz real siempre se conserva como propiedad JSON. Texto y atributos siguen siendo strings: 00123, true y fechas aparentes no se infieren como números, booleanos o fechas. Los atributos aparecen primero bajo @attributes; una hoja con atributos siempre incluye #text, incluso "". Una hoja sin atributos pasa a string. Hermanos consecutivos con igual nombre forman arrays; grupos intercalados como a/b/a se rechazan porque agruparlos cambiaría el orden.

    Los números y booleanos pasan a texto XML y vuelven como strings, con avisos de pérdida de tipo. Lexemas como 9007199254740993, 1.2300 y -0 se conservan; el aviso de precisión numérica es distinto de perder el tipo JSON. El desbordamiento numérico no finito falla. null y objeto vacío producen el mismo elemento vacío y vuelven como ""; un array de un ítem no recupera su intención de array. Un array raíz vuelve como objeto de hijos item repetidos, sin inferir array raíz. Revisa conteos y primeras ubicaciones de todos los avisos. No existe round-trip universal ni reparación automática.

    Un modelo de datos XML 1.0 acotado

    Nombres de 1–64 caracteres ASCII: comienzan con letra o guion bajo y continúan con letras, dígitos, guion bajo, guion o punto. El prefijo xml en cualquier capitalización, sintaxis de namespace y nombres inseguros relacionados con prototipos se rechazan sin alias ni renombrado. No cualquier clave JSON es nombre XML. JSON estricto rechaza duplicados, comentarios y extensiones. XML requiere raíz única completa, cierres con capitalización exacta y atributos distintos.

    Namespaces, DTD/DOCTYPE, declaraciones ENTITY, instrucciones de procesamiento (PI), contenido mixto de texto e hijos, hermanos intercalados, entidades desconocidas y XML mal formado se rechazan antes del parser externo. No hay soporte de XML general, HTML, XSD, XPath, XInclude o XSLT. Solo se decodifican una vez las cinco entidades predefinidas y referencias numéricas válidas; &amp;lt; se vuelve texto &lt;, no <. Texto CDATA se concatena en hojas; comentarios, delimitadores CDATA y declaración XML se omiten con avisos.

    CRLF y CR de XML se normalizan a LF. TAB/LF/CR literales de atributos pasan a espacios; referencias numéricas conservan esos valores. Los espacios de presentación entre hijos se omiten con aviso; los espacios de hojas siguen siendo datos. Una hoja XML vacía, no un documento vacío, pasa a string JSON vacío. Valores semánticos y representación textual son distintos: declaración, comillas, comentarios y formato no se reconstruyen.

    UTF-8, límites y exportación local completa

    Archivos UTF-8 estricto; extensión/MIME ayudan a seleccionar pero no prueban contenido válido. Un BOM UTF-8 inicial se quita con aviso; un segundo inicial se rechaza. CRLF/CR originales de editor o archivo permanecen en fuente retenida y coordenadas. XML sale sin BOM/declaración y con LF final; JSON respeta indentación sin forzar LF final. Descargas converted.xml (application/xml) o converted.json (application/json), con charset UTF-8.

    Entrada: 1.000.000 unidades UTF-16 y 2.000.000 bytes UTF-8; un archivo de hasta 2.000.000 bytes. Salida: 2.000.000 unidades y 4.000.000 bytes. JSON de entrada: 50.000 nodos y 100 niveles de contenedores; XML: 50.000 elementos, 50.000 atributos, 100 atributos por elemento, 200.000 tokens y profundidad 40. Datos decodificados: 1.000.000 unidades; JSON resultado: 100.000 nodos/profundidad 100. Trabajo propio: 8.000.000 unidades; análisis y escritura JSON: 1.000.000 cada uno. Detalles diagnósticos 20, familias de avisos 13, texto de ubicación 4.096 y metadatos diagnósticos 16.384 unidades. Todas las cotas se aplican juntas y no equivalen a una medición de toda la actividad del procesador. Plazo de conversión: 8.000 ms.

    Vista previa de solo lectura: hasta 50.000 unidades UTF-16 sin partir un par de unidades de un carácter suplementario. Copia/descarga incluyen siempre salida vigente completa; un fallo de portapapeles ofrece acción explícita de copia manual completa. Un proceso local cancelable (Worker) convierte sin subir documentos ni guardarlos en almacenamiento del navegador o ponerlos en URLs. Editar, modo/opciones, ejemplo, limpiar o cargar archivo invalidan salida/exportación anteriores. Error, límite, cancelación y tiempo agotado nunca publican resultados parciales. Sin JavaScript o proceso local disponible no hay conversión.
