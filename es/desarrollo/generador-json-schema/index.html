Genera JSON Schema desde documentos JSON completos

Infiere un esquema común desde una a veinte muestras JSON, revisa campos requeridos y comprueba cada documento completo localmente.

Espacio de trabajo de la herramienta

Generador de JSON Schema

Activa JavaScript para inferir un esquema localmente en tu navegador.

Cada editor contiene un documento JSON completo. Un array raíz sigue siendo un array. Los ejemplos orientan el esquema; no demuestran las reglas de tu dominio.

Hasta 20 muestras; 250.000 unidades UTF-16 por muestra y 500.000 en total; 1.000.000 bytes por archivo; profundidad 20; 50.000 nodos fuente totales; 2000 nodos inferidos; esquema de hasta 100.000 unidades UTF-16. Los presupuestos de trabajo pueden agotarse antes.

El procesamiento ocurre en tu navegador. Las muestras no se envían ni se guardan.

      Opciones del esquema

      La salida usa un vocabulario fijo y acotado de draft-07 con uniones de tipos y esquemas inline. Los objetos admiten propiedades adicionales. No se infieren formatos, enums ni relaciones entre campos.

      El esquema no acepta todas las muestras. La copia y descarga incluyen el esquema completo con tus reglas de requeridos manuales.

        Analiza documentos antes de generar

        Pega un documento JSON completo en cada editor o abre un archivo local .json UTF-8. Añade hasta veinte muestras independientes. Pulsa Analizar muestras, revisa los campos inferidos y luego Generar esquema. Son acciones explícitas: cargar un ejemplo no genera un resultado. Todas las muestras deben ser JSON estricto válido. Editores vacíos, claves decodificadas duplicadas, comentarios, JSONC/JSON5 y números con pérdida de precisión detienen la operación completa. No se descarta ninguna muestra que falle.

        Un editor con un array representa un documento array. Contribuyen todos sus elementos, incluidos los últimos; no se convierten en muestras independientes. Varios editores producen un esquema común para sus raíces. También se admiten raíces string, número, booleano y null.

        Ejemplo de array:

        [{"id":1},{"id":2,"nombre":"Ana"}]

        Con los requeridos inferidos, el array completo satisface este esquema:

        {
  "$schema": "http://json-schema.org/draft-07/schema#",
  "type": "array",
  "items": {
    "type": "object",
    "properties": {
      "id": {
        "type": "integer"
      },
      "nombre": {
        "type": "string"
      }
    },
    "required": [
      "id"
    ],
    "additionalProperties": true
  }
}

        Presencia, null y requeridos manuales

        id aparece en 2/2 objetos y es requerido por defecto; nombre aparece en 1/2 y es opcional. Marcar nombre como requerido produce el primer fallo en la instancia /0, keyword required, esquema /items/required, propiedad faltante nombre. Puedes exportar el esquema con el aviso visible de que no acepta todas las muestras. Se comprueba cada documento completo y se informa un primer fallo por muestra incompatible. Restablecer requeridos inferidos elimina todas las elecciones manuales, también las de otras páginas.

        En [ {"x":null}, {"x":"a"}, {} ], x está presente en 2/3 objetos, tiene tipos null/string y es opcional. Sin el objeto vacío, x es requerido y sigue siendo nullable. La ausencia afecta a la presencia; null afecta al tipo. En un objeto anidado, el denominador incluye sólo objetos observados en esa ubicación. Una observación demuestra presencia, no una obligación del dominio.

        [] genera type: "array" con items: {}: no se observó un tipo de elementos y items queda sin restricción. {} no revela propiedades. Enteros y fracciones se unen como number; otros tipos mixtos usan una unión type. Se combinan ramas de objeto y array inline sin deducir relaciones ni discriminadores. Por ello, el esquema puede aceptar combinaciones ausentes de los ejemplos.

        Draft fijo y sugerencias conservadoras

        El URI fijo es http://json-schema.org/draft-07/schema#. Se emiten $schema, type, properties, required, items, additionalProperties y title/description opcionales en la raíz. Todos los objetos son abiertos con additionalProperties: true. No hay selector de draft ni inferencia de reglas de formato, enums, rangos, patrones, referencias, tuplas o anyOf/oneOf/allOf.

        Activa las sugerencias antes de analizar para ver candidatos conservadores de email ASCII, URI HTTP(S) absoluta y fecha gregoriana válida YYYY-MM-DD. Al menos dos strings deben cumplir el mismo detector; un contraejemplo o un string de más de 1.024 unidades UTF-16 elimina el candidato. Los ejemplos idénticos cuentan como observaciones, pero no como evidencia independiente del dominio. Son metadata visible: format no se emite ni se comprueba con el validador actual. Copia el esquema y pégalo manualmente en el validador relacionado; los enlaces no transfieren datos.

        Límites, exportación completa y privacidad

        La entrada original permite 250.000 unidades UTF-16 por muestra, 500.000 en total y 1.000.000 bytes por archivo. Cada muestra admite profundidad 20 y 25.000 nodos fuente; el conjunto admite 50.000 nodos. El modelo permite 2.000 nodos inferidos y 2.000 propiedades, con profundidad lógica 20. El parseo dispone de 1.000.000 unidades de trabajo por documento; precisión de 1.000.000 compartidas; inferencia y validación de 5.000.000 compartidas cada una. No se garantiza alcanzar todos los máximos simultáneamente.

        El esquema completo permite 100.000 unidades UTF-16, 5.000 nodos JSON y profundidad JSON de parseo 60. La normalización conserva profundidad semántica 40, 5.000 visitas y 5.000 nombres. El título admite 256 unidades y la descripción 2.000; la indentación es de dos o cuatro espacios. Las rutas permiten 2.048 unidades; se publican hasta veinte diagnósticos y 8.192 unidades de texto diagnóstico. Cada página admite veinticinco entradas y 20.000 unidades de texto, con 8.192 por entrada. Una entrada excesiva invalida el análisis completo. Análisis y generación agotan el tiempo tras 8 segundos; las páginas tras 2 segundos. Los límites, cancelaciones y fallos operativos no publican un esquema ni comprobaciones parciales.

        Los archivos usan UTF-8 estricto. Se retira un BOM inicial con aviso y se conservan coordenadas del original visible; un segundo BOM inicial es inválido. Editar muestras, iniciar una carga, reanalizar o cambiar sugerencias invalida el snapshot y los requeridos elegidos. Cambiar requeridos u opciones invalida la salida. Cancelar termina el Worker; analiza nuevamente para continuar.

        Copia y descarga exportan el mismo esquema completo vigente, independientemente de la página de campos. La descarga usa schema.json, application/schema+json, UTF-8 sin BOM, LF y sin salto de línea final. Si falla el portapapeles, puedes copiar manualmente la salida completa de sólo lectura. El procesamiento es local: no hay envíos, URLs remotas, telemetría ni almacenamiento del contenido. Se necesitan JavaScript y un navegador compatible con Worker.
