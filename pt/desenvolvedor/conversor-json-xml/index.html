Converta JSON e XML localmente

Converta JSON estrito e um subconjunto de dados XML 1.0 localmente, com raízes explícitas, atributos, elementos repetidos e avisos de perdas.

Espaço de trabalho da ferramenta

XML perde tipos JSON e intenção de arrays de um item. Sem round-trip universal: null e objeto vazio podem ser o mesmo elemento vazio. XML → JSON mantém strings e a raiz real.

Use @attributes para atributos string e #text para texto de folhas. Arrays geram elementos repetidos. Nomes ASCII; sem namespaces ou conteúdo misto. Ler explicação completa do modelo

    Modelo e subconjunto aceito

    Usar a única propriedade raiz exige objeto JSON com uma propriedade: seu nome será a raiz XML. Envolver com nome raiz adiciona a raiz escolhida ao conteúdo. Array raiz usa o nome do item; arrays de propriedade repetem seu nome. Arrays devem ser não vazios e sem aninhamento direto. @attributes é objeto de valores string; #text é string permitida só sem filhos, inclusive vazia ou whitespace. Atributos XML retornam em @attributes; folha com atributos inclui #text. Filhos contíguos de mesmo nome viram arrays; grupos intercalados são rejeitados para manter a ordem. Uma folha XML vazia sem atributos retorna string JSON vazia; com atributos mantém #text="" dentro de um objeto. Números e booleanos perdem tipo; null, objetos vazios e arrays singleton perdem intenção. Subconjunto de dados XML 1.0: nomes ASCII de 1–64 caracteres, sem prefixo xml, namespaces, DTD ou instruções de processamento. Só entidades predefinidas e referências numéricas são decodificadas uma vez. Comentários, delimitadores CDATA, declaração e whitespace de apresentação são omitidos com avisos. Espaços de folhas mantidos; finais de linha XML e whitespace literal de atributos são normalizados. Sem inferência de tipos ou reparação automática.

    JSON → XML: escolha a raiz explicitamente

    Cole JSON estrito ou carregue um arquivo local .json, escolha JSON → XML e pressione Converter. A opção padrão Usar a única propriedade raiz (document) exige um objeto com exatamente uma propriedade comum. Envolver com nome raiz (wrap) acrescenta a raiz escolhida, inicialmente root; nunca extrai uma raiz existente automaticamente. Um array raiz usa o nome de item, inicialmente item; o ajuste não renomeia arrays sob propriedades. Escolha saída compacta ou formatada e 2 ou 4 espaços. A saída compacta conserva a indentação salva sem acrescentar whitespace de apresentação.

    {"catalog":{"@attributes":{"id":"00123"},"item":[{"@attributes":{"code":"a"},"#text":"uno & dos"},{"@attributes":{"code":"b"},"#text":"tres"}]}}
    <catalog id="00123"><item code="a">uno &amp; dos</item><item code="b">tres</item></catalog>

    @attributes é um objeto de valores exclusivamente string. #text deve ser string em folha sem filhos, mesmo vazio ou só espaços. Propriedades comuns criam filhos na ordem da fonte; arrays repetem o nome dessa propriedade. Um objeto @attributes: {} vazio é omitido com aviso; um valor vazio de atributo, como id="", é preservado. Objeto só com #text perde a envoltura JSON. Array raiz ["a","b"], com wrap raiz root e item item, produz <root><item>a</item><item>b</item></root>. Arrays devem ser não vazios e não podem estar diretamente aninhados; cada item heterogêneo é validado e um item não representável faz toda a conversão falhar.

    XML → JSON: strings e raiz real preservadas

    Cole XML ou carregue um .xml, escolha XML → JSON, selecione 2 ou 4 espaços e converta. A raiz real sempre permanece como propriedade JSON. Texto e atributos continuam strings: 00123, true e datas aparentes não viram números, booleanos ou datas por inferência. Atributos aparecem primeiro em @attributes; folha com atributos sempre inclui #text, mesmo "". Folha sem atributos vira string. Irmãos consecutivos de mesmo nome formam arrays; grupos intercalados como a/b/a são rejeitados porque agrupá-los alteraria a ordem.

    Números e booleanos viram texto XML e voltam como strings, com aviso de perda de tipo. Lexemas 9007199254740993, 1.2300 e -0 são preservados; aviso de precisão numérica difere da perda do tipo JSON. Estouro numérico não finito falha. null e objeto vazio produzem o mesmo elemento vazio e voltam como ""; array de um item não recupera sua intenção de array. Array raiz volta como objeto de filhos item repetidos, sem inferir array raiz. Revise contagens e primeiras localizações dos avisos. Não existe round-trip universal nem reparo automático.

    Um modelo de dados XML 1.0 limitado

    Nomes de 1–64 caracteres ASCII: começam com letra ou sublinhado e seguem com letras, dígitos, sublinhado, hífen ou ponto. Prefixo xml em qualquer capitalização, sintaxe de namespace e nomes inseguros ligados a protótipos são rejeitados sem alias ou renomeação. Nem toda chave JSON é nome XML. JSON estrito rejeita duplicados, comentários e extensões. XML exige uma raiz completa, fechamento com capitalização exata e atributos distintos.

    Namespaces, DTD/DOCTYPE, declarações ENTITY, instruções de processamento (PI), conteúdo misto de texto e filhos, irmãos intercalados, entidades desconhecidas e XML malformado são rejeitados antes do parser externo. Não suporta XML geral, HTML, XSD, XPath, XInclude ou XSLT. Só as cinco entidades predefinidas e referências numéricas válidas são decodificadas uma vez; &amp;lt; vira texto &lt;, não <. Texto CDATA se concatena em folhas; comentários, delimitadores CDATA e declaração XML são omitidos com avisos.

    CRLF e CR do XML normalizam para LF. TAB/LF/CR literais em atributos viram espaços; referências numéricas preservam esses valores. Espaços de apresentação entre filhos são omitidos com aviso; espaços das folhas são dados. Uma folha XML vazia, não um documento vazio, vira string JSON vazia. Valor semântico e representação textual diferem: declaração, aspas, comentários e formato não são reconstruídos.

    UTF-8, limites e exportação local completa

    Arquivos devem usar UTF-8 estrito; extensão/MIME ajudam na seleção, sem provar conteúdo válido. Um BOM UTF-8 inicial é removido com aviso; um segundo inicial é rejeitado. CRLF/CR originais de editor ou arquivo ficam na fonte retida e coordenadas. XML sai sem BOM/declaração e com LF final; JSON segue indentação sem forçar LF final. Downloads: converted.xml (application/xml) ou converted.json (application/json), charset UTF-8.

    Entrada: 1.000.000 unidades UTF-16 e 2.000.000 bytes UTF-8; um arquivo até 2.000.000 bytes. Saída: 2.000.000 unidades e 4.000.000 bytes. JSON de entrada: 50.000 nós e 100 níveis de contêineres; XML: 50.000 elementos, 50.000 atributos, 100 por elemento, 200.000 tokens e profundidade 40. Dados decodificados: 1.000.000 unidades; JSON resultado: 100.000 nós/profundidade 100. Trabalho próprio: 8.000.000 unidades; análise e escrita JSON: 1.000.000 cada. Detalhes diagnósticos 20, famílias de avisos 13, texto de localização 4.096 e metadados diagnósticos 16.384 unidades. As cotas se aplicam juntas e não medem toda a atividade do processador. Prazo de conversão: 8.000 ms.

    Prévia somente leitura: até 50.000 unidades UTF-16 sem dividir par de unidades de um caractere suplementar. Copiar/download sempre usam saída completa vigente; falha de área de transferência oferece ação explícita de cópia manual completa. Um processo local cancelável (Worker) converte sem enviar documentos, guardá-los no armazenamento do navegador ou colocar seu conteúdo em URLs. Editar, modo/opções, exemplo, limpar ou carregar arquivo invalidam saída/exportações anteriores. Erro, limite, cancelamento e tempo esgotado nunca publicam resultados parciais. Sem JavaScript ou processo local disponível não há conversão.
