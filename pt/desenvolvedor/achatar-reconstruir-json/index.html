Achate e reconstrua caminhos JSON no navegador

Converta JSON estrito em caminhos reversíveis com pontos ou colchetes e reconstrua mapas localmente, preservando valores vazios e tokens numéricos e rejeitando ambiguidades.

Espaço de trabalho da ferramenta

Achatar e reconstruir JSON

Ative o JavaScript para processar JSON localmente no navegador.

Operação

A raiz é $. Uma propriedade simples pode ser escrita como $.name; uma chave literal com ponto usa $["a.b"]; um índice de array usa $[0]. O mapa vazio {} é inválido; {"$":{}} representa um objeto vazio. Há conflito quando um caminho é prefixo de outro, como {"$.a":1,"$.a.b":2}. Arrays esparsos são rejeitados, por exemplo {"$[2]":"x"}. Nem todo mapa com pontos pode ser reconstruído sem ambiguidade. A operação inversa verifica os limites novamente.

Usar um resultado muda para a operação inversa. Os limites são verificados novamente; a operação não é executada automaticamente.

Arquivo: 8.000.000 bytes; entrada: 2.000.000 unidades UTF-16; profundidade: 200; nós: 100.000; entradas: 50.000; saída: 2.000.000 unidades UTF-16.

Limites de trabalho

Limites de trabalho: 1.000.000 unidades de análise, 1.000.000 de transformação e 1.000.000 de serialização. Caminhos aceitam 200 segmentos, 10.000 unidades cada e 1.000.000 no total; índices vão até 99.999. Nem todos os máximos podem ser garantidos ao mesmo tempo.

O processamento permanece neste navegador. Sem envios, URLs remotas, rascunhos salvos ou conteúdo do documento em URLs ou registros.

Carrega o exemplo da operação selecionada.

{"user":{"name":"Ana"},"items":[1,{},[]],"a.b":null,"":true}

    Achate ou reconstrua com uma ação explícita

    Cole JSON estrito ou abra um arquivo .json UTF-8 local. Escolha Achatar JSON para criar um mapa de caminhos ou Reconstruir JSON para refazer um documento a partir de um mapa; depois execute a operação. Carregar um exemplo, abrir um arquivo, editar o texto ou alterar opções nunca inicia uma transformação. Os dois modos compartilham uma página e uma URL canônica.

    A entrada de exemplo compartilhada é:

    {"user":{"name":"Ana"},"items":[1,{},[]],"a.b":null,"":true}

    Com caminhos dot, o mapa minificado é:

    {"$.user.name":"Ana","$.items[0]":1,"$.items[1]":{},"$.items[2]":[],"$[\"a.b\"]":null,"$[\"\"]":true}

    Com caminhos bracket, o mapa minificado é:

    {"$[\"user\"][\"name\"]":"Ana","$[\"items\"][0]":1,"$[\"items\"][1]":{},"$[\"items\"][2]":[],"$[\"a.b\"]":null,"$[\"\"]":true}

    Os dois mapas reconstroem os dados de entrada. A saída padrão usa dois espaços; os exemplos estão minificados para facilitar a comparação dos caminhos.

    Caminhos, raízes e valores vazios

    O formato é um objeto JSON não vazio, sem envelope. Cada chave é um caminho absoluto a partir de $; cada valor é primitivo, um objeto vazio {} ou um array vazio []. Contêineres não vazios são inferidos pelos segmentos tipados. Uma raiz primitiva ou vazia usa uma única entrada $, como {“$”:null} ou {“$”:{}}. Um objeto ou array raiz não vazio é representado por suas folhas descendentes. Um mapa vazio {} é inválido porque não identifica um valor raiz.

    $ significa raiz, $.name significa a propriedade simples name, $[“a.b”] significa a propriedade literal a.b e $[0] significa o índice zero do array. $[“0”] é uma propriedade chamada 0; $[0] é um índice de array. A notação dot usa strings JSON entre colchetes para chaves com pontos ou delimitadores, como a.b, x[y], aspas, barras invertidas, Unicode ou a string vazia. A notação bracket escreve cada propriedade como uma string JSON entre colchetes. A reconstrução aceita dot, bracket e misturas das duas. Este é o formato de caminhos da ferramenta, não JSONPath completo: não há curingas, filtros, slices ou separadores personalizados.

    Objetos e arrays vazios permanecem como valores folha explícitos, por exemplo {“$.settings”:{},“$.items”:[]}. Arrays devem ser densos desde zero. Um caminho de propriedade e um caminho de índice não podem compartilhar o mesmo contêiner. A reconstrução rejeita aliases duplicados, uma folha com descendentes, valores do mapa que sejam objetos ou arrays não vazios e arrays esparsos. Por exemplo, {“$.a”:1,“$[0]”:2} exige tipos de contêiner incompatíveis; {“$.a”:1,“$.a.b”:2} conflita entre folha e descendente; {“$[2]”:“x”} deixaria índices ausentes. Nenhum valor é sobrescrito, preenchido com null ou escolhido por «o último vence».

    JSON estrito e valores

    A entrada precisa ser JSON estrito: comentários, JSONC, JSON5 e sintaxe inválida são rejeitados. Chaves duplicadas depois de decodificadas, como {“a”:1,“\u0061”:2}, falham em vez de substituir um valor silenciosamente. Inteiros grandes, decimais, zero negativo e expoentes são emitidos a partir dos tokens numéricos originais, incluindo 9007199254740993, 0.10000000000000001, -0 e 1E+02. Um aviso de precisão descreve a aproximação interna do parser, não um arredondamento da saída. Números fora do intervalo do parser, como 1e400, falham explicitamente.

    O percurso de ida e volta dentro dos limites preserva valores JSON, chaves, posições de arrays e tokens numéricos. Não preserva espaços de origem, a escrita exata dos escapes ou a ordem original dos membros dos objetos. A saída é reformatada com LF, sem BOM nem quebra de linha final.

    Limites e saída completa

    Arquivos locais têm limite de 8.000.000 bytes e a entrada de 2.000.000 unidades UTF-16. A transformação aceita profundidade 200, 100.000 nós JSON, 50.000 entradas no mapa, caminhos com até 200 segmentos e 10.000 unidades UTF-16 cada, e saída com até 2.000.000 unidades UTF-16. Análise, transformação e serialização têm, cada uma, orçamento de 1.000.000 unidades de trabalho. Índices de array vão até 99.999. A operação expira após 15 segundos; recuperar a saída completa leva no máximo 5 segundos. São mantidos até 100 diagnósticos e uma prévia de 20.000 unidades. Nem todos os máximos podem ser garantidos ao mesmo tempo.

    Uma prévia truncada pode ser JSON incompleto. Copiar JSON e Baixar JSON recuperam toda a saída atual, inclusive o conteúdo além do limite da prévia. Se a área de transferência falhar, use o campo completo para cópia manual. Os arquivos baixados usam json-flattened.json ou json-reconstructed.json, MIME JSON e UTF-8. Usar resultado como entrada recupera o snapshot completo, muda para o modo inverso e verifica os limites novamente. A operação não é executada automaticamente.

    O processamento permanece neste navegador. Arquivos, cópia e downloads exigem uma ação sua; não há envios, URLs remotas, rascunhos salvos nem entrada ou saída em URLs ou registros. Cancelar mantém a entrada e as opções. Editar, alterar modo ou opções, limpar ou carregar outro arquivo invalida o resultado anterior.
