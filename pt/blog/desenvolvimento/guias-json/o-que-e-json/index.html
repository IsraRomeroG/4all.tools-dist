O que é JSON? Guia prático da sintaxe JSON

Entenda o que é JSON, como sua sintaxe funciona e por que ele é usado para trocar dados estruturados.

A ideia principal

JSON é um formato de texto usado para representar dados e compartilhá-los entre programas. Objetos agrupam pares de chaves e valores, e arrays contêm listas ordenadas de valores.

{"produto":"Caderno","preço":49.9,"disponível":true}

JSON é um formato de texto usado para representar dados e compartilhá-los entre programas. A sigla significa JavaScript Object Notation, mas seu uso vai além de JavaScript: diferentes linguagens conseguem ler e gerar JSON. Suas regras permitem escrever informações como o nome de um produto, seu preço e uma lista de cores de maneira que outro programa consiga interpretar. Você pode encontrar esse texto em uma resposta de aplicativo, em configurações ou em um arquivo com a extensão .json. Referência do formato JSON.

Um exemplo simples de JSON

Imagine a ficha de um produto. Em JSON, ela pode ser escrita assim:

{
  "produto": "Caderno",
  "preço": 49.9,
  "disponível": true
}

Esse documento contém três informações: o produto se chama Caderno, seu preço é 49.9 e ele está disponível. Os dados são fictícios; o exemplo não especifica uma moeda.

Cada informação aparece como um par de chave e valor. A chave funciona como a etiqueta de um campo: "produto" identifica a informação, e "Caderno" é o valor desse campo. Da mesma forma, "preço" é a chave cujo valor é o número 49.9.

Os sinais organizam a ficha:

  • As chaves { e } delimitam um objeto, que reúne esses pares.
  • Os dois-pontos : separam o nome de cada campo do seu valor.
  • As vírgulas , separam os pares, sem aparecer depois do último.
  • As aspas duplas " delimitam nomes de campos e valores de texto.

O valor true significa verdadeiro. Aqui, ele indica disponibilidade porque esse é o significado escolhido para o campo. O nome do campo não determina seu tipo: 49.9 é um número porque foi escrito como número, sem aspas.

Para que serve JSON?

JSON ajuda programas a trocar informações com uma estrutura comum. O software ainda precisa saber o que fazer com cada campo. Veja três situações:

Troca de dados entre aplicações. Um sistema de catálogo prepara o JSON do caderno e o envia a uma loja. A loja interpreta os campos e usa os valores para mostrar o nome, o preço e a disponibilidade na tela. Essa comunicação pode passar por uma API, uma interface que permite a programas se comunicarem. JSON é uma opção de formato para os dados dessa comunicação.

Configuração. Uma pessoa ou um programa escreve preferências em um arquivo JSON. Ao iniciar, uma aplicação lê os valores para escolher o idioma ou habilitar uma função. Ela precisa reconhecer os nomes dos campos e os valores permitidos.

Exportação e armazenamento. Uma aplicação gera texto JSON com seus registros e o grava em um arquivo. Outra aplicação pode interpretar esse arquivo para importar os dados, desde que compreenda sua estrutura.

Em todos esses casos, os sistemas precisam combinar o significado dos campos. Alterar o nome de um campo esperado por uma API pode impedir seu uso, mesmo que o documento continue seguindo as regras de JSON.

Objetos, listas e os seis tipos de dados

Podemos ampliar a mesma ficha sem mudar os três campos iniciais:

{
  "produto": "Caderno",
  "preço": 49.9,
  "disponível": true,
  "cores": ["azul", "preto"],
  "vendedor": {
    "nome": "Ana",
    "cidade": "Puebla"
  },
  "observações": null
}

O campo "cores" contém um array, uma lista ordenada delimitada por colchetes [ ]. Seus dois itens são textos separados por vírgula. Já "vendedor" contém outro objeto, com os campos "nome" e "cidade". Um objeto dentro de outro é uma estrutura aninhada.

Estes são os seis tipos de valores que JSON permite:

Tipo Exemplo da ficha Como ler
Texto, ou string "Caderno" Uma sequência de caracteres entre aspas.
Número 49.9 Um valor numérico, sem aspas.
Booleano true Verdadeiro ou falso: true ou false.
Array, ou lista ordenada ["azul", "preto"] Uma sequência de valores.
Objeto {"nome":"Ana","cidade":"Puebla"} Um conjunto de pares de chave e valor.
Nulo null Um valor nulo explícito.

Neste catálogo, combinamos que "observações": null significa que não há observação registrada. Essa é uma convenção da aplicação: null não é automaticamente o mesmo que zero, texto vazio ou um campo ausente.

Um documento JSON completo também pode conter apenas uma lista ou um valor simples, como 49.9. A ordem dos itens de uma lista é significativa; o significado dos campos de um objeto não deve depender da ordem em que aparecem. Use nomes únicos dentro de cada objeto, pois chaves repetidas podem receber tratamentos diferentes entre programas. Essas regras estão descritas no padrão JSON, RFC 8259.

As aspas mudam o tipo do valor

Todos os seis documentos abaixo são JSON válido. Em cada par, a diferença é a presença de aspas no valor:

Campo Tipo original Valor como texto
Preço {"preço":49.9} {"preço":"49.9"}
Disponibilidade {"disponível":true} {"disponível":"true"}
Observações {"observações":null} {"observações":"null"}

"49.9" é texto com dígitos; "true" é texto, não um booleano; "null" é texto, não um valor nulo. Portanto, colocar aspas não é apenas uma mudança visual. Isso pode alterar a maneira como uma aplicação aceita ou utiliza a informação.

Qual é a diferença entre JSON, um arquivo e os dados de um programa?

Você pode encontrar a mesma informação em três situações diferentes:

Conceito O que significa
Texto JSON A informação escrita conforme as regras do formato.
Arquivo .json Um arquivo que armazena esse texto.
Dados utilizados por um programa Os valores obtidos ao interpretar o texto, que o programa pode consultar e modificar.

O texto pode chegar pela rede sem existir como um arquivo no seu computador. Quando um programa o interpreta, transforma essa representação em valores que consegue utilizar. Essa leitura é chamada de parsing. A operação de transformar dados em uma representação textual é chamada de serialização.

Apesar do nome, JSON não é um programa em JavaScript. É um formato de dados inspirado em parte da sintaxe dessa linguagem. JavaScript também permite construções, como funções, que não são valores JSON.

Gerar texto e salvar um arquivo são operações diferentes. Em JavaScript, por exemplo, JSON.stringify() pode gerar o texto. Outra operação precisa gravá-lo para criar ou atualizar um arquivo. Da mesma forma, renomear qualquer arquivo para terminar em .json apenas muda seu nome; o conteúdo ainda precisa seguir as regras do formato.

Cinco erros comuns de sintaxe em JSON

Sintaxe é o conjunto de regras que organiza o texto. Um programa que verifica essas regras, chamado parser, pode rejeitar uma entrada por causa de uma única vírgula ou aspa.

Cada entrada abaixo é deliberadamente inválida e vem acompanhada de uma correção válida. As regras correspondem a JSON padrão, conforme a referência de JSON no MDN.

1. Nome do campo sem aspas

Inválido — nomes de campos precisam de aspas duplas:

{produto:"Caderno"}

Correção válida:

{ "produto": "Caderno" }

2. Aspas simples

Inválido — aspas simples não delimitam textos em JSON:

{'produto':'Caderno'}

Correção válida:

{ "produto": "Caderno" }

3. Vírgula depois do último campo

Inválido — a vírgula separa itens; não deve aparecer antes do fechamento:

{"preço":49.9,}

Correção válida:

{ "preço": 49.9 }

4. Vírgula ausente entre campos

Inválido — falta separar os dois pares:

{"produto":"Caderno" "preço":49.9}

Correção válida:

{ "produto": "Caderno", "preço": 49.9 }

5. Booleano com letra maiúscula

Inválido — True não é um valor permitido:

{"disponível":True}

Correção válida:

{ "disponível": true }

Os valores especiais são escritos exatamente como true, false e null, sempre em minúsculas. JSON padrão também não admite comentários. Para números decimais, use ponto, como 49.9, mesmo que você normalmente escreva números com vírgula em português.

Use aspas retas no código: um editor que as substitua por aspas tipográficas pode tornar o documento inválido. Já um número entre aspas continua sendo JSON válido; ele apenas passa a ser texto.

Se um programa rejeitou seu documento, veja como encontrar e corrigir erros de sintaxe JSON, com um exemplo completo e correções mínimas.

Como abrir, criar e validar um arquivo JSON

Abrir ou criar o arquivo

Abra o arquivo em um editor de texto ou código. Para criar um, copie o primeiro exemplo deste guia em um documento novo. Não é necessário executar o conteúdo para lê-lo ou editá-lo.

Depois de modificar um valor, verifique a sintaxe. Salve o conteúdo como texto em UTF-8, com um nome como produto.json. Confirme o nome completo: alguns editores podem acrescentar .txt, resultando em produto.json.txt. Os acentos de "preço" e "disponível" fazem parte das chaves e devem ser preservados.

Formatar não é o mesmo que validar

Operação O que ela verifica ou altera
Formatar Organiza espaços, recuos e quebras de linha para facilitar a leitura.
Validar a sintaxe Verifica se o texto segue as regras de JSON.
Validar contra um esquema Verifica restrições declaradas para os dados, como campos obrigatórios e tipos esperados.

Um esquema descreve requisitos para os dados. Por exemplo, pode exigir que o preço seja um número. Essa é uma etapa distinta da verificação de sintaxe. Introdução ao JSON Schema.

Reparar uma entrada também é outra operação: ela modifica o conteúdo para tentar corrigir problemas. Uma indicação de “JSON válido” não garante que os dados atendam aos requisitos da aplicação ou correspondam à realidade.

Faça uma pequena experiência

Suponha que nosso catálogo exija um preço numérico. Use o primeiro exemplo, com três campos, e acompanhe a sequência em um validador de JSON padrão:

  1. Verifique o exemplo original. O resultado esperado é sintaxe válida.
  2. Acrescente uma vírgula depois do último true, antes de }. O resultado passa a ser inválido, por causa da vírgula final.
  3. Remova essa vírgula. A sintaxe volta a ser válida.
  4. Coloque o preço entre aspas. A sintaxe continua válida, mas o preço agora é texto.

Depois do quarto passo, você terá:

{
  "produto": "Caderno",
  "preço": "49.9",
  "disponível": true
}

Um validador de sintaxe aceita esse documento. O catálogo pode rejeitá-lo porque exige um número no preço. Uma validação de esquema poderia detectar essa diferença se a restrição estivesse declarada; não presuma que todo validador ofereça essa função.

Para terminar, restaure 49.9 sem aspas, valide novamente e salve produto.json. As mensagens de erro variam entre ferramentas, mas a sequência esperada é: válido, inválido, válido e válido com mudança de tipo.

Opcional: ler e gerar JSON com JavaScript

Se você já está aprendendo programação, este exemplo mostra como ler o produto, alterar seu preço e gerar outro texto. O bloco seguinte é JavaScript, não JSON:

const textoJson = '{"produto":"Caderno","preço":49.9,"disponível":true}';
const dados = JSON.parse(textoJson);

console.log(dados.produto); // Caderno
dados["preço"] = 59.9;

const textoAtualizado = JSON.stringify(dados, null, 2);
console.log(textoAtualizado);

JSON.parse() interpreta o texto. Neste caso, produz um objeto cujos campos podemos consultar ou modificar; para outros documentos, pode produzir uma lista ou um valor simples.

JSON.stringify() gera texto JSON a partir de valores compatíveis. O 2 pede um recuo de dois espaços. A primeira saída é Caderno. Depois, aparece:

{
  "produto": "Caderno",
  "preço": 59.9,
  "disponível": true
}

As aspas simples externas delimitam uma string em JavaScript; elas não fazem parte do texto JSON armazenado nela. O comentário também pertence ao JavaScript. A conversão tem limitações conforme os valores utilizados, e este código apenas exibe o resultado: ele não salva um arquivo.

Opcional: quando usar JSON, CSV ou XML?

O formato adequado depende da estrutura dos dados e do que o sistema que os recebe aceita:

Formato Situação em que costuma ser útil
JSON Dados organizados em campos, listas e estruturas aninhadas, como nossa ficha de produto.
CSV Tabelas simples, com registros em linhas e campos separados por um delimitador.
XML Informações ou documentos organizados com elementos e marcação.

Um catálogo com uma linha por produto pode caber bem em CSV. Já a ficha com uma lista de cores e os dados agrupados do vendedor encontra uma representação direta em JSON. XML permite estruturar conteúdo com elementos e atributos. As referências de CSV e XML detalham suas regras.

Volte ao exemplo do caderno, altere um valor e verifique o resultado. Ao salvar, confira tanto a sintaxe quanto os tipos que a aplicação espera.
